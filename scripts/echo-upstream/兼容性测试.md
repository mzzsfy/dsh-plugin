# echo-upstream(LLM 模拟器)兼容性测试

定位:仓库公共 LLM 测试服务,兼容性测试的 LLM 夹具层。非宿主插件——不进 bundles、无 activation 面,本文件按测试服务形态裁剪分层:L1=单元层(node:test),L2=拉起探活(CLI boot + HTTP 探活),L3=功能面(协议与场景断言),L4=宿主链路交叉(经 dsh-llm-pi-gateway 真实上游消费)。命令:`node scripts/echo-upstream.mjs`,实现 `scripts/echo-upstream/`(server/protocol/streaming/scenarios/recorder 五模块)。

| 层 | 范围 | 手段 |
|----|------|------|
| L1 单元层 | 协议装配/流式序列/场景解析/留档契约全量单测(test/ 4 文件 19 用例 + helpers) | `node --test "scripts/echo-upstream/test/*.test.mjs"` |
| L2 装载层 | CLI boot、端口绑定、stdout 提示行、三协议探活 | CLI 拉起 + curl |
| L3 功能面 | 双协议非流式/流式、thinking、错误注入、usage 覆写、模型目录、留档 | HTTP 客户端逐断言 |
| L4 共存层 | 宿主真实链路(pi-ai → fetch → 本服务):header 注入实证、流式对话、usage 采集 | 见 dsh-llm-pi-gateway/兼容性测试.md echo 接收器节 |

执行顺序 L1 → L2 → L3 → L4,前层失败即止。

## CLI 契约(L2 判据)

```
node scripts/echo-upstream.mjs                       # 默认端口 18123,留档系统临时目录
node scripts/echo-upstream.mjs --port 0              # 随机端口(stdout 打印实际端口)
node scripts/echo-upstream.mjs --log <文件>          # 留档 jsonl 路径
node scripts/echo-upstream.mjs --tokens <in>,<out>   # usage 覆写(默认 1/1)
node scripts/echo-upstream.mjs --models a,b,c        # 模型目录扩展(默认单模型)
```

boot 判据:stdout `[echo-upstream] listening 127.0.0.1:<port> log=<path>`;`GET /models` 200。

## L3 功能面断言

| # | 操作 | 预期 |
|---|------|------|
| 1 | POST `/v1/chat/completions`(任意含 /messages 外路径)非流式 | 200 openai chat.completion 形状,内容固定 `echo-upstream-fixed`,model 回显请求值,usage 默认 1/1/2 |
| 2 | POST 含 `/messages` 路径非流式 | 200 anthropic message 形状,stop_reason `end_turn`,usage 默认 1/1 |
| 3 | GET 含 `/models` 路径,带/不带 `anthropic-version` 头 | anthropic 列表形状(has_more)/openai 列表形状(object: list) |
| 4 | 非法 JSON body | 不拒绝,照常 200 响应(model 为 null) |
| 5 | 非流式请求体 `stream:true` + openai 路径 | `text/event-stream`,chunk 序列:role 首块 → content delta(`echo-upstream-fixed`)→ finish chunk(含 usage)→ `data: [DONE]` |
| 6 | `stream:true` + anthropic 路径 | event 序列:message_start → content_block_start(text) → content_block_delta(text_delta) → content_block_stop → message_delta(usage.output_tokens) → message_stop |
| 7 | 模型名以 `-think` 结尾 | 流式:openai 含 `reasoning_content` delta(`echo-upstream-thinking`)/anthropic 含 thinking content_block + `thinking_delta`;非流式:openai `message.reasoning_content`/anthropic content[0] 为 thinking 块 |
| 8 | 模型名以 `-err429` / `-err500` 结尾 | 对应 HTTP 错误码 + JSON 错误体(`echo-upstream-injected`) |
| 9 | 模型名以 `-drop` 结尾 + 流式 | 部分块后连接中断,无 `[DONE]` 终止帧;非流式不受影响 |
| 10 | 模型名以 `-slow` 结尾 + 流式 | 块间 200ms 级间隔(耗时观测) |
| 11 | `--tokens 100,200` | 双协议非流式与流式 usage 全部为 100/200(openai total=300) |
| 12 | 任意请求后读留档 jsonl | 逐行 JSON:at/method/path/headers(小写键)/body/scenario(default|think|err429|err500|drop|slow),既有字段(at/method/path/headers/body)形态不变 |

## 分层注意点

- 场景只经**模型名后缀**触发,与 providers 路由零配置对接(gateway 按模型选路由);请求体 `stream` 是唯一流式开关(标准语义),不经模型名。
- 形状保真度:openai 流式 usage 终块 `choices: []`(对齐真实 `stream_options.include_usage`);anthropic thinking 块无 `signature` 字段(真实 API 有,宿主 UI 断言不依赖,暂不模拟)。
- 错误注入无挂死形态(`-slow` 用间隔非阻塞),测试链路不得因本服务卡死。
- 留档逐行 JSON 是 gateway 兼容测试的断言契约,响应场景字段只增不改。
- Windows 下 node:test 对"逐测试起停 server + fetch"存在退出期 libuv 断言形态(src\win\async.c)——本目录测试文件以**文件级共享实例**(模块顶层 await 起服 + 顶层 after 收尾)规避;新增测试文件沿用该形态,禁止逐测试拉起。

## L4 宿主链路交叉

本服务的宿主侧消费验证由 `packages/dsh-llm-pi-gateway/兼容性测试.md`「echo 接收器」节承载(header 注入三通道实证、禁用三路径、热更新切端口)。LLM 模拟器增强后解锁的夹具面:

- think-expand 流式组(#11-#18):宿主 providers 指向本服务,模型选 `-think` 变体,发送回合产生真实思考流。
- usage-dash/回合费用:经 `--tokens` 给出非平凡 usage,真实对话回合产生可统计的用量样本。
- gateway 流式链路:替代"非流式 echo 导致 stream ended TRANSPORT"的形态差,流式对话全程无 TRANSPORT 噪音。
- mce:model-capability-editor providers 配置指向本服务目录(`--models` 扩展模型)。
