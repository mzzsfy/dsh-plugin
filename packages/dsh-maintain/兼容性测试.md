# dsh-maintain 兼容性测试

包定位:设置内「版本与运维」页(settings.section 分区,order 45),dsh 本体运维面板——npm dist-tag 版本检查、追踪通道切换、更新内容查看、安全重启。受管A/B升级依赖发现到受管布局(.dsh-maintain):不可用时 API 返回409,界面安装按钮禁用;底层升级原语和本地脚本冒烟不是宿主profile健康验收。host 半区以 webServer 具名路由暴露 8 条 `/api/maintain/*` 接口供浏览器半区调用;配置持久化双形态:0.1.7+ 走 profile 条目 `maintain` config 节(静态 `Config` 导出生成节表单,volatile 经 configEditor 写回原地热更),legacy(≤0.1.6)走 settings `maintain` 命名空间,检查结果仅存内存不落盘。轮询依赖宿主 timer、版本检查与面板保存依赖 settings/configEditor、重启直接终止宿主进程(不依赖启动器能力),全部软依赖:缺失或方法面不齐时干净降级留痕,不阻塞装载、不加载崩溃。

### L2 装载层

- 冒烟覆盖:scripts/smoke-load.mjs 遍历 packages/ 下全部含 package.json 的目录(symlink/junction 一并收),逐个动态 import 各包 main——OK/FAIL 逐行输出,入口缺失打 SKIP,任一包加载失败即 exitCode 1;`--profile` 参数切换为遍历 profile node_modules/@mzzsfy 测安装副本。本包 main 为 src/index.js,在清单内:宿主半区顶层依赖(@deepseek-ai/schemastery 等)缺失或自身命名导出损坏当场暴露。src/client.js 非 main,不被该脚本 import,其装载由本层 boot 判据与 L3 覆盖。
- 隔离环境 boot 判据:本包经 `dsh plugin add @mzzsfy/dsh-maintain --profile <隔离profile>` 注入(完整命令含 --profile 指向隔离 profile,不得对开发宿主所在 profile 执行;bundle patch 在该 profile root 插入 id=maintain 行),重启一次宿主完成首装载;判据 = activation live + diagnostics findings 0 + 无 pending/装载错误 + 页面无 `Failed to load plugins`。顶层 inject 仅声明 webServer:宿主缺 webServer 时 fiber 不激活即干净禁用,不 pending 拖死 boot。
- 软依赖降级日志表(出现以下文案属降级预期,不判失败,但须核对与宿主实际能力一致):

| 日志文案 | 含义 | 面板形态 |
|---|---|---|
| 「timer 服务方法面不可用,自动轮询停用(面板可手动检查更新)」 | timer 缺失或方法面不齐 | 顶部警示「自动轮询未运行(宿主定时服务不可用)…」,手动检查不受影响 |
| 「settings 服务方法面不可用,版本检查停用,通道/设置保存不可用」 | legacy 宿主 settings 缺 register 方法面(宿主代际过低信号) | 自动检查与保存不可用(手动「刷新」仍会发起真实检查,勿点),版本区以默认值呈现 |
| 「检测到未过期的升级锁(可能存在残留升级子进程),升级端点保持拒绝直至锁过期」 | 残留升级锁 | 升级触发被 409 拒绝直至锁过期 |

- 升级锁文件位于系统临时目录(`dsh-maintain-upgrade.lock`),仅在真实触发安装后产生;测试前若存在且未过期,先删除再测,否则安装入口被 409 锁定干扰 L3 心智(本流程不触发安装,仅存量卫生检查)。本包无数据目录,检查结果仅内存,重启即清,测试不留脏数据。

### L3 功能面断言

受管升级依赖受管布局(.dsh-maintain):缺失时服务端 upgrade API 回409,安装按钮点击被宿主回绝(仅瞬态门:升级进行中/重启中,版本状态与残留锁全放行)。兼容性测试不得发起升级、不得执行网络安装验收；原语单测仅验证隔离编排,不代表host ready。

断言于隔离宿主上以 playwright 执行;选择器与文案均对照 src/client.js 校准。沿用既有等待约定:页面加载等 9s、导航点击后等 2s、渲染断言前等 2.5s(页面调宿主版本 API,网络慢时控件延迟到达)。默认态指页面初次进入、无升级历史、无弹窗时的形态。

## L4 共存层

- @mzzsfy/dsh-common-tools(硬依赖,package.json 显式 dependencies + `dsh.client.external`):装载行 `maintain-dsh-common-tools` 随本包 `cordis.patch.yml` 自带,宿主按包名合并成一份 client 模块,装本包即可独立运行;依赖范围 `^0.4.0`,版本与兼容窗口规则见 [DEVELOPMENT/client-dependency.md](../../DEVELOPMENT/client-dependency.md)。client 半区经该模块取 toast:操作失败右下角浮出提示,只有单一形态(依赖必装);模块缺失属装载失败,不是降级分支。同装验证面板与浮条(#dsh-maintain-upgrade-float,仅升级过程及落定终态出现,SPA 切页不消失)不互相干扰。
- dsh-settings-nav-icons(导航图标):client 半区声明双键 `{ '版本与运维': 'wrench', 'dsh-maintain': 'wrench' }`,经 `window.__navicIcons.register` 注册或 `__navicIconQueue` 入队(本插件晚于其就绪时由其启动排空)。同装时验证设置导航「版本与运维」项带扳手图标;该插件缺失时仅图标不渲染,导航项仍可点,不判失败。
- 设置分区共存:settings.section 分区 id=maintain、order 45、label「版本与运维」,与其他插件分区按 order 排序共存;0.1.7+ 宿主同时经 `settings.configure({auto:false})` 关闭原生自动生成页,避免与本包自定义面板重复;`/api/maintain/*` 8 条路由与 profile 条目 `maintain` config 节为本包独占,全家桶下无注册冲突。
- 样式契约:样式注入与渲染点均带 data-plugin=@mzzsfy/dsh-maintain(client-id 测试锁定);全家桶下任一其他插件 HMR 重建后,本包面板样式不得丢失(样式被误删表现为控件裸排,命中即回归)。
- 全家桶最大风险交叉:本包能力直接改写 dsh 本体(全局 npm 安装)并重启宿主——全家桶环境一旦触发安装/重启即整体作废,比单包测试更严格:任何形态下(含 market 页面与侧栏误触)不得触发安装与重启,共存验证只做只读断言。
- 共存底线:任意插件组合下页面无 `Failed to load plugins`;全家桶共启后本包 activation live、diagnostics findings 0。

## 专项注意

- 「受管升级」入口已可用但兼容性轮次禁止触发:只做只读断言(按钮/弹窗形态),不点击「开始安装」,不运行网络安装型脚本验收——兼容性环境一旦真实安装即整体作废。候选验证链路(npm ls + CLI 冒烟)由包内单测以真实子进程覆盖。
- 其他真实上游交互仍需单独说明:「刷新」会请求registry dist-tags;「更新内容」会请求GitHub Releases;「重启宿主」需隔离宿主且仅允许经明确批准的兼容性轮次触发。
- 环境前提:隔离宿主经 `dsh plugin add @mzzsfy/dsh-maintain --profile <隔离profile>` 注入并重启完成首装载(不得对开发宿主所在 profile 执行);宿主须提供 webServer(顶层 inject,缺失即插件整体不激活);registry 默认 `https://registry.npmjs.org`,隔离环境不可达时按 #8/#9/#17 的兜底分支判,不误报失败。

- 误判防范:
  - 控件数延迟:页面调宿主 `/api/maintain/status`,网络慢时控件数延迟到达,断言前等 2.5s;
  - 徽章/通道 option 随上游 dist-tags 与运行版本实时浮动:「有新版本 x」的 x 为通道目标版本,option 文本带「  (版本号)」后缀——断言按形态正则或 includes 通道名,不锁字面值;「上次检查」时间自然走动,不锁具体值;
  - 升级卡默认不渲染(仅当升级进行中或存在历史时出现):「升级」卡缺席是预期,不是功能缺失;运维入口以「重启」卡为准;

  - 「版本与运维」文本同时出现在设置导航项与本页标题两处,断言 #3 选择器必须锚定导航容器(叶子节点匹配),防命中页内标题造成假阳性。
- 断言保留记录:原 5 项全部保留融入,无一删除——原 1→新 1、原 2→新 2、原 3→新 3、原 4→新 4、原 5→新 14。仅新 14 措辞按现源码修正:检查/升级入口的按钮现文案为「刷新」「安装」(原「检查/升级」字样仍存于「检查中…」「上次检查」「升级」卡题等副本文案),预期由「(含检查或升级)且含重启」收紧为「含刷新、安装、重启宿主」;其余按源码补全了选择器、placeholder 与预期文本。另:面板警示文案存在源码残留——pollRunning=false 通知原文为「自动轮询未运行(宿主定时服务不可用);可手动点『检查更新』,其余能力不受影响。」,其中「检查更新」为源码残留(实际按钮名为「刷新」),断言该通知时按源码原文匹配,不按按钮名纠正。

## 维度检查点(补充)

1. **托管矩阵**:至少覆盖一种真实托管形态(A/B 或 nvm/install-b)下的「检查 → 候选验证 → 切换 → 重启」;失败(候选坏/网络断)必须保留原版本继续服务。
2. **门控 fail-closed**:门控面不可用时拒绝升级;有活跃 agent/job 时拒绝且不可越过;重启的 force 语义单独验证。
3. **锁**:验证超时/切换后状态不确定时保锁并强退;人工核验后可解锁;并发第二请求被拒。
4. **外部源**:GitHub 页面抓取上限与缓存只存成功结果;Release 缺失给出可读提示与源站链接;npm registry 不可达不影响已装版本展示。
5. **路由固定行为**:升级 API 返回 409、安装入口禁用是本轮已知形态,不得写成「已启用」;测试只做只读断言,不触发真实升级。
