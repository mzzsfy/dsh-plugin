# dsh-maintain 兼容性测试

包定位:设置内「版本与运维」页(settings.section 分区,order 45),dsh 本体运维面板——npm dist-tag 版本检查、追踪通道切换、更新内容查看、受管 A/B 安装、升级前检查、安全模式、升级进度与安全重启。受管安装的布局(`<prefix>/.dsh-maintain` 下 install-a/install-b + `dsh_link` 目录链接 + 命令入口改写)**在首次升级时自建,不要求预先存在**;安装发现(`discoverRunningInstall`)失败时 upgrade 受理回 409「受管安装不可用」,而布局不合格/候选验证/切换失败属 200 受理后落定失败(`upgrade.last.ok=false`,带原因),两种情况面板都不禁用「安装」——入口只按通道目标未知(含非法 semver)与瞬态门(升级进行中/重启中)禁用。已装版本取受管链接当前指向槽的清单版本,与运行版本(进程启动时缓存)分离,链接版本严格领先运行版本时提示重启后生效。升级前 `POST /api/maintain/preflight` 汇总布局/权限/磁盘/锁/state/npm/Node/插件兼容检查,插件硬不兼容普通升级 409 拒绝;安全模式只禁用可恢复的用户插件并记录 `safe-mode.json`;新宿主 `appReady` 后核对运行版本与插件健康,把 `state.json` 从 `awaiting-restart` 收尾为 `healthy`/`degraded`。底层升级原语和本地脚本冒烟不是宿主 profile 健康验收。host 半区以 webServer 具名路由暴露 13 条 `/api/maintain/*` 接口供浏览器半区调用,每条处理器首行回问宿主闸门(`connection.requestRejection`),写路由另带 Origin↔Host 同源比对与精确 `application/json` content-type 校验;配置持久化双形态:0.1.7+ 走 profile 条目 `maintain` config 节(静态 `Config` 导出生成节表单,volatile 经 configEditor 写回原地热更),legacy(≤0.1.6)走 settings `maintain` 命名空间,检查结果仅存内存不落盘。轮询依赖宿主 timer、版本检查与面板保存依赖 settings/configEditor、重启直接终止宿主进程并按 `RESTART_EXIT_CODE`(75)离场,全部软依赖:缺失或方法面不齐时干净降级留痕,不阻塞装载、不加载崩溃。

### L2 装载层

- 冒烟覆盖:scripts/smoke-load.mjs 遍历 packages/ 下全部含 package.json 的目录(symlink/junction 一并收),逐个动态 import 各包 main——OK/FAIL 逐行输出,入口缺失打 SKIP,任一包加载失败即 exitCode 1;`--profile` 参数切换为遍历 profile node_modules/@mzzsfy 测安装副本。本包 main 为 src/index.js,在清单内:宿主半区顶层依赖(@deepseek-ai/schemastery 等)缺失或自身命名导出损坏当场暴露。src/client.js 非 main,不被该脚本 import,其装载由本层 boot 判据与 L3 覆盖。

### L3 功能面断言

受管安装的真实执行不在兼容性轮次:布局(`<prefix>/.dsh-maintain`)在首次升级时自建,`discoverRunningInstall` 失败才在受理阶段回 409「受管安装不可用」,布局不合格/候选验证失败/切换失败属 200 受理后 `upgrade.last.ok=false`。面板「安装」入口只按通道目标未知与瞬态门(升级进行中/重启中)禁用——非受管布局下按钮照常可点,点了会被服务端拒绝并在升级卡/浮条给出原因,这是当前已知形态。兼容性测试不得发起升级、不得执行网络安装验收;原语单测仅验证隔离编排,不代表 host ready。

断言于隔离宿主上以 playwright 执行;选择器与文案均对照 src/client.js 校准。沿用既有等待约定:页面加载等 9s、导航点击后等 2s、渲染断言前等 2.5s(页面调宿主版本 API,网络慢时控件延迟到达)。默认态指页面初次进入、无升级历史、无弹窗时的形态。

## 维度检查点(补充)

1. **托管矩阵**:至少覆盖一种真实托管形态(A/B 或 nvm/install-b)下的「检查 → 候选验证 → 切换 → 重启」;失败(候选坏/网络断)必须保留原版本继续服务。
2. **门控 fail-closed**:门控面不可用时拒绝升级;有活跃 agent/job 时拒绝且不可越过;重启的 force 语义单独验证。
3. **锁**:验证超时/切换后状态不确定时保锁并强退;人工核验后可解锁;并发第二请求被拒。
4. **外部源**:GitHub 页面抓取上限与缓存只存成功结果;Release 缺失给出可读提示与源站链接;npm registry 不可达不影响已装版本展示。
5. **路由与退出语义**:13 条路由都必须在业务面前回问宿主闸门(401/403),写路由另拒跨源;重启/升级落定的退出码为 75(非零),托管默认策略(systemd `Restart=on-failure`、supervisord `autorestart=unexpected`)据此拉起——这两条按固定行为验证,不得写成「已启用但未测」。

## 判据补充

上表 D01/D02/D06/D07/D11 的检查点全部通过才可宣称本窗口兼容;未实际执行升级路径时,D06/D07 只能记 P 并写明阻断原因,不得以「入口可点」替代。
