# dsh-maintain 兼容性测试

包定位:设置内「版本与运维」页(settings.section 分区,order 45),dsh 本体运维面板——npm dist-tag 版本检查、追踪通道切换、一键安装(升级/重装/回退)、更新内容查看、安全重启。host 半区以 webServer 具名路由暴露 9 条 `/api/maintain/*` 接口供浏览器半区调用;配置持久化双形态:0.1.7+ 走 profile 条目 `maintain` config 节(静态 `Config` 导出生成节表单,volatile 经 configEditor 写回原地热更),legacy(≤0.1.6)走 settings `maintain` 命名空间,检查结果仅存内存不落盘。轮询依赖宿主 timer、版本检查与面板保存依赖 settings/configEditor、重启依赖启动器 appExit,全部软依赖:缺失或方法面不齐时干净降级留痕(面板降级提示),不阻塞装载、不加载崩溃。

## 测试分层与执行流程

| 层 | 内容 | 手段 |
|---|------|------|
| L1 单元层 | test/ 下 10 个 `*.test.mjs`,覆盖纯逻辑/上游拉取/升级执行器/发布说明/host 路由集成/重启等待/client 守卫/双实现对拍(清单见下) | 包目录 `node --test "test/*.test.mjs"` |
| L2 装载层 | 全包冒烟加载 + 隔离宿主 boot 干净降级判据 | 仓库根 `node scripts/smoke-load.mjs`(本包在清单内)+ 隔离 profile 启动 |
| L3 功能面层 | 入口与骨架 5 项 + 版本信息 5 项 + 设置分区 2 项 + 运维入口 2 项 + 确认弹窗 3 项(即下节断言全集,共 17 项) | playwright 页面断言(隔离宿主) |

### L2 装载层

- 冒烟覆盖:scripts/smoke-load.mjs 遍历 packages/ 下全部含 package.json 的目录(symlink/junction 一并收),逐个动态 import 各包 main——OK/FAIL 逐行输出,入口缺失打 SKIP,任一包加载失败即 exitCode 1;`--profile` 参数切换为遍历 profile node_modules/@mzzsfy 测安装副本。本包 main 为 src/index.js,在清单内:宿主半区顶层依赖(@deepseek-ai/schemastery 等)缺失或自身命名导出损坏当场暴露。src/client.js 非 main,不被该脚本 import,其装载由本层 boot 判据与 L3 覆盖。
- 隔离环境 boot 判据:本包经 `dsh plugin add @mzzsfy/dsh-maintain --profile <隔离profile>` 注入(完整命令含 --profile 指向隔离 profile,不得对开发宿主所在 profile 执行;bundle patch 在该 profile root 插入 id=maintain 行),重启一次宿主完成首装载;判据 = activation live + diagnostics findings 0 + 无 pending/装载错误 + 页面无 `Failed to load plugins`。顶层 inject 仅声明 webServer:宿主缺 webServer 时 fiber 不激活即干净禁用,不 pending 拖死 boot。
- 软依赖降级日志表(出现以下文案属降级预期,不判失败,但须核对与宿主实际能力一致):

| 日志文案 | 含义 | 面板形态 |
|---|---|---|
| 「启动器未提供 appExit,就地重启能力关闭(面板按钮禁用)」 | 启动器未挂 appExit | 重启按钮 disabled,旁注「当前启动方式不支持就地重启」 |
| 「timer 服务方法面不可用,自动轮询停用(面板可手动检查更新)」 | timer 缺失或方法面不齐 | 顶部警示「自动轮询未运行(宿主定时服务不可用)…」,手动检查不受影响 |
| 「settings 服务方法面不可用,版本检查停用,通道/设置保存不可用」 | legacy 宿主 settings 缺 register 方法面(宿主代际过低信号) | 自动检查与保存不可用(手动「刷新」仍会发起真实检查,勿点),版本区以默认值呈现 |
| 「检测到未过期的升级锁(可能存在残留升级子进程),升级端点保持拒绝直至锁过期」 | 残留升级锁 | 升级触发被 409 拒绝直至锁过期 |

- 升级锁文件位于系统临时目录(`dsh-maintain-upgrade.lock`),仅在真实触发安装后产生;测试前若存在且未过期,先删除再测,否则安装入口被 409 锁定干扰 L3 心智(本流程不触发安装,仅存量卫生检查)。本包无数据目录,检查结果仅内存,重启即清,测试不留脏数据。

## 专项注意

- 「检查升级」类按钮一律**只看不点**,唯一例外:#15/#16 允许点「安装」开窗与「取消」关窗;「开始安装」「重启宿主」任何情况下(含双击/误触)禁点。逐按钮说明:
  - 「刷新」:真实请求 registry dist-tags(非破坏,但产生真实上游流量,且关机窗口内会被 409 拒绝造成噪音);
  - 「更新内容」:真实请求 GitHub Releases;
  - 「安装」:点击仅打开确认弹窗、无网络副作用,故为例外放行(仅限 #15/#16 流程内各点一次);弹窗内「开始安装」触发真实 npm install 改写全局宿主,任何情况下禁点;
  - 「重启宿主」:两段式——第一次点击仅进入确认态(文案变「确认重启」;有活跃工作时变「仍要重启(N 项活跃工作)」),第二次点击立即真实重启宿主,误触双击即毁掉隔离宿主,整轮测试环境作废,任何情况下禁点。

- 环境前提:隔离宿主经 `dsh plugin add @mzzsfy/dsh-maintain --profile <隔离profile>` 注入并重启完成首装载(不得对开发宿主所在 profile 执行);宿主须提供 webServer(顶层 inject,缺失即插件整体不激活);registry 默认 `https://registry.npmjs.org`,隔离环境不可达时按 #8/#9/#15/#17 的兜底分支判(#15 变更说明行呈「通道最新版未知」分支),不误报失败。
