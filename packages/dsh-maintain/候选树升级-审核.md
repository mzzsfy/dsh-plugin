# 候选树升级规格审核记录

> 历史文档(2026-11-10 注):候选树规格已被 [透明升级-设计.md](透明升级-设计.md) 取代并在实现中落地;本文审查结论仅针对被替换的规格。

## 结论与范围

本轮对[候选树升级BDD](./候选树升级-BDD.md)进行独立设计审查。
三轮全文审查与末轮限定复审后，核心协议审查无剩余阻断。
**这不是代码实现验收或生产升级批准**：G-1至G-5尚未执行，当前不能部署。

原地安装旧[规格](./升级根治-BDD.md)仍未通过；本轮没有修复旧实现、重启
宿主或改动用户PowerShell循环、profile、PATH及全局安装树。

## 事实纠正

前轮PoC只有两步删除/创建junction和少量Node导入测试：

- 删除旧junction后创建新junction不是原子操作，短时间不证明无窗口。
- 一个进程的模块缓存表现不证明所有晚加载或资源访问免疫切换。
- 保留旧树不证明回指操作和生产数据恢复永远成功。
- 生产使用PowerShell npm shim；裸while不会识别管理器版本指针或屏障。

以上推论已在新规格明确撤回。新设计选择树外稳定监督入口＋最终唯一发行
目录＋原子控制记录，不再依赖junction换向。本轮只读核实PowerShell默认
解析dsh.ps1、Node/nvm物理身份与npm载体影响prefix。

## 独立审查与修正

### 首轮：六组核心阻断

| 发现 | 处置 |
|------|------|
| suspended create→assign之间存在未归属进程 | 要求JOB_LIST原子create-with-job，handle不可继承；不支持即拒绝部署 |
| 请求只有去重承诺，无持久accept与历史结果 | 接受先写control，再产生副作用；永久results账本、payloadDigest、step/startIntent |
| 包库存被当成完整模块解析图 | 分开安装图与(require/import)模块探针边，固定Node/conditions，明确动态未知覆盖边界 |
| production失败/监督器死亡缺许可撤销边 | 失败立即持久blocked，再终止核验；serving旧owner丢失不得自动重拉 |
| 全记录revision使事务自己的写入导致CAS失败 | 分开revision与activationGeneration，发布比较active选择代际 |
| abandoned mutex被当成进程树消亡 | 线程固定、持久owner身份/epoch、线程失效整体fail-stop；核验旧owner/named jobs，未知不接管 |

同时采纳树外seal/inventory避免自引用、版本化生成物策略与来源关联键、
隔离env/path映射进报告。没有把未实测的原语或未知上游兼容性伪装为事实。

### 第二轮：请求schema与恢复入口

- 请求缺expectedActivationGeneration，存在A→B→A授权代际漏洞；已补字段，
  纳入payloadDigest，接受与发布双核对。
- accepted不在严格事务enum；已统一accepted及终态集合，terminal是标记。
- 一个暂停非终态安装可能阻断所有合法恢复；已定义kind=control的
  terminate/cancel/activate/recover/restart及授权、目标operation/attempt、
  expectedRevision/epoch，控制操作不被单安装限制一律拒绝。
- 统一G-1措辞为原子create-with-job，不保留旧assign窗口。

### 第三轮：中断控制请求的生命周期

managementIntent中断后若直接覆盖会丢失旧accepted记录与历史去重；若拒绝
覆盖会恢复死锁。已规定：核验旧副作用→持久写旧请求中断result→确认结果→
清旧intent→接不同新ID。未知进程仍blocked，结果写失败仅允许独占域终止/
核验旧job，不创建child或改变active。

### 末轮限定复审

独立reviewer仅复核上述续接顺序及相邻状态，确认R3-1关闭：
中间崩溃仍有结果去重，同ID返回既有终态，未知进程不被请求终态掩盖。
六维(内部一致性、完整性、歧义性、外部一致性、结构合规、可执行性)
均无剩余阻断。该结论只评价文档定义，不代表测试全部通过。

## 保持阻断发布的验收门

- G-1：Windows原子替换、全局mutex、原子Job归属及恢复的隔离故障注入。
- G-2：真实候选安装、全运行依赖来源与native/lifecycle产物策略。
- G-3：独立DSH_HOME/数据目录/私有echo的真实候选就绪与解析验证。
- G-4：候选半装、未知writer、首次生产假host失败、恢复及请求重放矩阵。
- G-5：稳定工具依赖快照、无生产面测试写入、无子进程残留。

这些门当前未完成。建议下一步只做G-1隔离原语实验；不先实施插件或改生产。
任一原语无法满足契约应重设计，不添加TTL放行或活体npm fallback。

## 产品取舍

只管理一个production HOME/端口；不管理未知外部消费者，不添加多HOME扩展。
候选准备失败保留旧服务；真实首次启动失败允许持久停机，不默认用旧代码读
已经变化的生产数据。版本回退需用户显式数据兼容或恢复授权。
首次采用需要另行部署许可，停止旧裸循环、改为绝对路径受管监督入口。
不能继续承诺原启动行不改。
