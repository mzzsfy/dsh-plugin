# 候选树升级隔离验收报告

> 历史文档(2026-11-10 注):本文验收对象为已被替换的候选树规格,现方案见 [透明升级-设计.md](透明升级-设计.md)(A/B 双目录已实施)。文中"当前不存在可验收的完整产品"仅指当时规格,不代表当前实现。

## 总结论

**验收不通过——当前不存在可验收的完整产品；可验收的原语与候选可行性得到
真实证据，其中一项关键原语假设被实测证伪。** 本轮为隔离实测，未触碰生产
HOME、profile、3080、全局安装树与用户 PowerShell 循环。

证据目录 `%TEMP%/dsh-candidate-accept-<随机后缀>/`
（windows/、candidate/、evidence/）。所有子进程经 PID+创建时间双重核验
清理，无残留；真实 LLM 零消耗。

## G-1 Windows 原语：partial-not-passed（18/20 pass，2 fail）

- **证伪项（原样保留，不刷绿）**：无锁并发 reader 下 `File.Replace` 观测
  6,559 次 missing + 1,586 次共享冲突；`ReplaceFileW` 观测 8,977 次
  missing + 2,300 次共享冲突（各 200 次替换、数万次完整旧/新读，invalid
  字节为 0）。**“无锁读者总能读到完整旧/新记录”不成立。**
- **协调条件通过**：同 Global named mutex 内读取+替换：14,339 次完整读、
  0 异常。规格 INV-II（发布/启动同互斥域）从“应当”变为“实测必要条件”。
  读异常必须显式 blocked，不得按缺失放行——与规格一致，现有了实现级证据。
- locked destination 真实 Win32 error 32 拒绝、旧字节保留；三阶段杀进程
  保留完整旧/旧/新记录（非断电测试）；Global mutex 并发拒绝、owner 进程
  kill abandoned、owner 线程死亡而进程仍活 → abandoned 不能推定进程死亡
  （规格恢复条款获得实证）。
- **JOB_LIST 全部通过**：创建时归属（resume 前 inJob=true、active=1、
  handle 不可继承）；父死子孙全灭；未 resume 父死同样消亡；
  TerminateJobObject 计数归零；三类创建失败无 fallback、无孤儿；
  no-KILL_ON_JOB_CLOSE 负例真实留下 2 个活进程（仅清理本探针进程）。
- 未测：真实断电/介质耐久、access-denied、拒绝终止、跨登录会话、生产
  全部写点矩阵。

## G-2 候选安装：部分支持，未过门

真实 unique prefix、隔离 userconfig/cache/env，钉定
`@deepseek-ai/dsh@0.2.0-rc.2`：安装 exit 0、root 版本精确命中、
`npm ls --all` exit 0。**未做**：tarball SRI→逐文件来源对拍、
native/lifecycle 产物审计、whole-manifest 摘要基线——按规格不得宣称
“来源完整”。

## G-3 隔离启动：部分支持，未过门

allowlist env + 隔离 DSH_HOME/HOME/数据目录，候选自身 bin.js 冷启动：
绑定随机端口、打印 token URL；带 token 请求返回 303（铸 cookie 语义，
与仓库 compat 协议一致），可达性成立。首轮探针不带 token 断言 `/` 返回
200 属断言缺陷，已如实记录为 harness-assertion-invalid 并以带 token 复验
修正。**未做**：浏览器渲染、插件加载诊断、echo LLM 链路、完整 ready ACK、
boot 前后 whole-manifest 对比（首轮对比为空，但非 seal 语义）。

## G-4/G-5 完整成品：NOT_IMPLEMENTED，验收不通过

独立只读核对（读码，未运行）确认：现源码仍是活体全局 npm 路径——
`index.js:268` 默认 `npm install -g`、`:583-592` 宿主内
`runUpgradeWithRetry`、`upgrade.mjs:70-75` `shell:true` spawn；锁损坏视为
无锁（`index.js:253-263`）、写失败吞掉（`:566-569`）、未知 writer 仅锁到
过期（`:613-616`）。规格中的稳定启动器、事务管理器、请求/结果账本、
startIntent、sealed/激活发布、blocked/recover 控制面**一行代码都不存在**。
临时探针不是产品，不构成 G-4/G-5 验收。

## 结论与下一步

1. 架构原语底座成立：协调互斥下的原子指针 + JOB_LIST 进程树是可实现的
   （本机 PS 5.1/NTFS 实测）；无锁读取假设已被证伪并淘汰。
2. 候选树可行性成立：真实安装与隔离启动均真实跑通。
3. **不得宣称方案已验收**：G-4/G-5 缺实现。下一步是实施管理器本体
   （feat flow、TDD），实施完成后再跑完整故障矩阵验收。
4. 原语证据与本报告保留在临时目录，仓库内仅本报告落档。
