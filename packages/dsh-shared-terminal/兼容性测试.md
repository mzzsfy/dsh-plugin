# dsh-shared-terminal 兼容性测试

包定位:注册唯一工具 `terminal`,让 AI 与用户通过官方 Sidebar `terminal` tab 操作同一 Session-owned shell,并对 Host xterm active viewport 做只读快照。写入通道随宿主代际:0.2.0 与 0.2.1-alpha.2 借用官方 xterm UI 的 input attachment;0.2.1-rc.2 起插件自持 attach 泵(空闲冷却 10s 释放)。client 半区另有只读自愈(6s 巡检)与固定 `contentId` 面板复用。

本包**精确允许表**:仅 `0.2.0-rc.1`、`0.2.0-rc.2`、`0.2.1-alpha.2`、`0.2.1-rc.2`、`0.2.1-rc.3`、`0.2.1-rc.4`、`0.2.1-rc.5`、`0.2.2-alpha.3`、`0.2.2-rc.1`、`0.2.2-rc.2` 支持功能面;其他版本 Host 启动检查不匹配时**干净禁用并告警**(不注册工具,不崩宿主)。`dsh.hostMin = "0.2.0-rc.1"`。这是本仓库唯一以精确版本白名单约束功能面的包,测试必须先核对宿主版本。

分层与维度定义见 [测试与隔离方法](../../docs/兼容性测试/测试与隔离方法.md)(L1-L4 执行协议)与 [兼容性检查总纲](../../docs/兼容性测试/兼容性检查总纲.md)(D01-D15 维度);宿主升级回归要求见 [DEVELOPMENT/dsh-api-alignment.md](../../DEVELOPMENT/dsh-api-alignment.md) 条款 3。

## 测试分层与执行流程

| 层 | 内容 | 手段 |
|---|---|---|
| L1 单元层 | `test/run.mjs` 自定义入口:真实 BrowserTerminal/xterm 的宽字符、组合字符、软换行、scrollback、alternate buffer、resize、队列与关闭竞态;UI 附着夹具(follow/resize 或 attach 命令帧);attach 泵/只读契约/wait 屏幕/工具视图 | 包目录 `npm test -- <隔离宿主目录>`,或 `DSH_TEST_HOST=<宿主目录>`;连跑 3 轮 |
| L2 装载层 | 冒烟加载 + 隔离宿主 boot:activation live、findings 0、页面无失败插件、工具出现在会话工具列表 | `node scripts/smoke-load.mjs` + `node scripts/compat/run.mjs --version <v> --only dsh-shared-terminal --keep` |
| L3 功能面 | 下节断言表,真机终端 + playwright | 隔离宿主 + 真实 shell(cmd/pwsh/bash) |
| L4 共存层 | 与官方 `tool-pwsh`/终端侧栏、`dsh-shell-select`(Windows shell 接管)、`dsh-tool-gate`(工具占位)、全家桶 | 同装 boot + 终端操作回归 |

执行顺序 L1 → L2 → L3 → L4,前层失败即止。测试 helper 从隔离宿主显式解析 Controller/Tools,不依赖 ESM `NODE_PATH`;未提供宿主且解析链缺限定版本时明确失败,不得跳过。子会话夹具:`tool.test.mjs` 以 `origin=subagent` 与 `parentSession+delegationDepth` 两种 header 调用 open/list/read,断言 `INVALID_ARGS` 且不触达 Controller(子会话终端无用户侧栏入口)。

## 维度检查点(补充)

1. **版本允许表**:不在表内的宿主只验「干净禁用 + 告警」,不验功能;0.2.0 系与 0.2.1-rc.2+ 两代通道各跑一轮。
2. **attach 泵**:控制器私有形态不匹配时自愈重抢一次;重抢失败返回 `TERMINAL_ERROR`;空闲冷却后新附着 sequence 归零。
3. **只读自愈**:真实裁切且无附着泵才接管;仅只读但无裁切不抢控制权;缩窗后 2s 内恢复。
4. **多面板**:同 `contentId` 复用;跨会话引用 `TERMINAL_UNAVAILABLE`;不重复注册 `terminal` 工具。
5. **权限与安全**:命令以系统用户权限执行、不受 Agent sandbox/approval 约束;测试只跑无害命令;`close`/`write` 断言先读后写。
6. **终端查询应答**:真实 ConPTY 下 resize 触发 `ESC[6n`;安装应答器后 PTY 侧只出现 1 次请求、bash 正常绘制、屏幕无 `;1R` 残片;未安装时请求重试到 2–3 次且 bash 不绘制。`write submit=true` 在 POSIX shell + normal buffer 下 payload 以 `0x15` 开头,alternate buffer 与非 POSIX shell 不加。

## 判据补充

上表 D01/D02/D05/D06/D07/D09 的检查点必须有本窗口真机证据;0.2.0 系与 0.2.1-rc.2+ 两代各一轮;不在允许表的宿主只记「干净禁用」,不得据此宣称功能兼容。

## L3 功能面断言

## 专项注意

- **精确版本白名单**:功能面只对允许表承诺。宿主升级后先核对 Controller 形态与本表,不在表内的版本只能验证"干净禁用",不能验证功能。
- **权限边界**:命令由系统用户权限执行,不受 Agent sandbox/approval 约束;测试只在隔离工位临时目录内运行无害命令,禁止格式化/删除类操作。
- **真实终端**:`test/` 的 subprocess 边界是替身,不等于真实 shell E2E;L3 必须在真实宿主 + 真实 shell 上执行。
- **危险操作**:`close` 会销毁终端与泵;`write` 会真实执行输入。断言顺序先读后写,避免把测试命令留在用户终端。
- **多面板**:固定 `contentId` 是 0.4.3 起的契约;旧版本行为不同,跨版本证据不可复用。
- **判定不越界**:0.2.1-rc.2 上 `Controller` 无 `write/resize` 公开方法是宿主演进,不是缺陷;插件未命中允许表时的禁用是合法降级。

## 判据

L1 三轮全绿(允许表内宿主)+ smoke 通过 + L2 activation live/findings 0/页面无失败插件/工具注册 + 上表 L3 全部 ✓(条件格按成立形态判)+ L4 与 shell-select/tool-gate/全家桶共存通过。0.2.0 系与 0.2.1-rc.2+ 两代通道必须各有一轮真实终端证据;未执行格记 P。
