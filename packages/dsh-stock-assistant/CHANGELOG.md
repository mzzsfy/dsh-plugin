# 更新日志

## 0.6.0（2026-11-10）

### 存储改为控制面与缓存分域、每条记录一个文件

整域单文件时每次写入都要重写全部内容，K 线与目录缓存能把文件撑到几 MB；一条记录写坏就整域打不开。数据源字段改名那次故障正是被这个结构放大的。

- **控制面与缓存分成两个数据域**：`stock_assistant`（自选、别名、标记、分组、数据源与路由、近期幂等操作）与 `stock_assistant_cache`（目录、日历、K 线），互不牵连
- **按记录各写一个文件**：默认 json backend 下是 `~/.dsh/storages/stock_assistant/control/root.json` 与 `~/.dsh/storages/stock_assistant_cache/cache/<键>.json`。改自选只重写 `root.json`，拉一节 K 线只写它自己那个文件
- **坏记录只丢自己**：按记录布局下宿主才有坏记录备份能力，**校验失败**的记录被移成 `<键>.json.bak.<时间戳>` 后跳过，不再让整个域打不开（不可解析的文档宿主只会当作缺失，不留备份）
- **旧单文件自动迁移**：首次打开时宿主把旧 `~/.dsh/storages/stock_assistant.json` 里的 `control/root` 复制进新目录；未声明的旧缓存表不迁移（旧键含冒号，在 Windows 上不能当文件名），旧文件原样保留
- **缓存键改成路径安全字符**：`kline_<实例>_<市场>_<周期>_<代码>`、`catalog_<实例>_<市场>`、`calendar_<实例>_<市场>`；段内非安全字符折掉后附 64 bit 哈希，避免不同代码折进同一个文件
- **控制记录读不出来时不再覆盖**：控制域新增初始化标记 `meta/state`。首次安装（记录与标记都没有）才初始化空自选；标记存在而记录缺失（损坏、版本不认或被宿主跳过）直接停止激活并给出数据目录路径，原文件保持不动 —— 宿主对不可解析的记录不会备份，写空就等于把自选覆盖掉

### 修复存量数据字段改名让插件整体未激活

0.5.0 把数据源凭据字段从 `credentialEnv` 改名为 `credentialRef`（严格对象），迁移却只写在 `openState` 里。数据域在 `storageDomain.open` 阶段就先按新 schema 校验存量记录，`single` 布局的 JSON 单元又不支持坏记录备份跳过，于是数据域打开直接失败，插件 host 半区整体不注册路由：面板只剩 `Unexpected token 'o', "not found" is not valid JSON`，自选行情永远停在加载态。

- **归一放进数据域 schema**：读入时把旧字段就地改成 `credentialRef`，校验与迁移在同一层发生，不再依赖「打开之后」才跑的代码；新旧字段并存时以新字段为准，只带新字段的条目不受牵连
- **读出来就是新字段**：数据域把归一结果作为记录值使用，任何一次 control 记录写入都以新格式整体落盘（只写缓存不会升级 control 记录）
- **失败原因落日志**：数据域或依赖初始化失败时输出错误码、原因与坏记录位置，清理自身失败也不会盖掉原始原因
- **客户端不再贴解析器报错**：非 JSON 响应翻成「股票工具服务不可用（HTTP 状态码）」；请求被中止（超时/页面重置）按原样抛出，不伪装成服务故障
- **回归锁**：真实 `DomainFacility` 打开存量旧记录、真实 json backend 的单文件迁移与坏记录隔离、控制记录缺失提示、客户端 404 与非 JSON 响应

### 多笔成本改取最低价

- **成本基准取最低价**：同一只股票填了多条成本时，列表行内盈亏、概览持仓合计、详情「持仓盈亏」与 K 线图例成本% 都按最低那一条算（原来按等权均价）
- **每条成本仍各自显示百分比**：标记列表里每条成本各算「现价相对它」，卖价收益按成本价计
- **标记页写明口径**：价格标记下方直接说明「多笔成本取最低价作为成本，盈亏按它算；每条成本单独显示与现价的百分比，卖价收益也按成本算」

## 0.5.0（2026-11-10）

### 接入 Finnhub 与宿主凭据存储

- **密钥交给宿主保管**：数据源密钥不再只认环境变量，改成写进 DSH 的凭据存储。设置页填一次值就走宿主的凭据服务，配置里只留引用名（如 `DSH_STOCK_FINNHUB_TOKEN`），插件状态与快照里都不留副本
- **按操作解析**：每次取数前重新解析一次密钥，换了密钥下一次刷新就生效，不必重启插件；密钥缺失直接报 `AUTH`，不会把空串当密钥发出去
- **只写自己声明的引用**：写密钥的接口只接受当前数据源正在使用的引用名，插件不越界碰别人的密钥空间
- **新来源 Finnhub**：美股实时报价。只能当报价源——免费档的 K 线与盘口都标着 Premium Access Required。它没有批量端点，一只一次请求，所以 `maxQuoteBatch` 是 1，官方也明确不建议持续轮询。默认不进路由：没配密钥时它是个用不了的实例，配好密钥后在设置页把美股报价的源指过去即可

### 修复纽约所美股被当成纳斯达克取价

东财的美股 secid 前缀（105 纳斯达克 / 106 纽约 / 107 美交所）本该由交易所决定，此前却只在搜索缓存里查，缓存落空就一律默认 105。缓存是内存态、24 小时过期，进程重启后整张表清空，于是纽约所的标的（如阿里巴巴）重启后必然取不到报价，界面上整行显示占位符。

- **候选顺序改为**：搜索缓存 > 交易所静态前缀 > 其余美股市场号。缓存退化为加速手段，正确性由交易所前缀保证，不再依赖此前的搜索行为
- **前缀兜底**：静态前缀只对应一个市场号，而纽约所实际横跨 106 与 107。首轮落空的美股再用剩余市场号批量补一次，多只标的合成一次请求，已命中的不重复问
- **顺带收敛**：K 线与报价改用同一套 secid 推导；探针里原本重复逐前缀试探的循环删掉，探针与真实取价不再走两套路径

## 0.4.0（2026-11-09）

悬浮盯盘、价格标记、K 线指标、常显分组与八市场扩展。

### 悬浮盯盘

窗口右下角常驻一块小面板，切走面板、关掉会话都不影响它继续更新。

- **列表与图形两种形态**：列表模式一屏显示多只标的的现价与涨跌幅，点任意一行切到该只的图形；图形模式是自绘的分时曲线，`‹ ›` 只在勾选的标的里循环
- **按分组勾选**：勾选面板按「置顶 / 各组 / 未分组」分区排列，与列表同一份切面；分区头显示数量并可整组勾上或清掉，盯盘通常就是盯某个板块
- **只盯你勾选的**：点 `☰` 逐个勾选观测目标。从没勾过时退回自选前 5 只作为初始值；一旦动过就完全按你的选择，全部取消勾选就是一只都不盯，不会再被悄悄加回来
- **可拖动**：按住标题条拖动，位置落在本地，越界自动收回可视区；窗体内保留纵向手势给列表滚动
- **刷新跟着设置走**：间隔取设置页的刷新间隔，不再固定 15 秒。底部用暂停/播放图标切换自动刷新，悬停给出当前间隔，切换时用 toast 回执；不再用像状态标签的「监听中」。全部收市（含午休）后降到一分钟一拍：列表模式九拍读只读快照、一拍真刷新；图形模式九拍完全不发请求、第十拍真刷新（切到某只标的后第一拍例外，先拉一次分时，见下）。那一拍真刷新不能省——只读快照回放的是缓存，不重算交易时段，单靠它永远发现不了开市；代价是收盘后开市最多要等十拍才恢复实时。图形模式的分时曲线不进缓存（每拍都是真上游），所以收市后必须彻底停掉。时段判断按 `receivedAt` 在自己拉的和面板的之间取最新的一份：面板不在前台时宿主会停掉主动采集，面板那份会一直停在最后一个交易时段上
- **数据不额外要**：列表优先用面板已有的报价快照渲染，自己的刷新结果回来后再按 `receivedAt` 择优，所以打开就能看到数字，不用等一轮上游往返
- **入口在主操作行**：`悬浮盯盘 / 收起盯盘` 与自选、市场、搜索、刷新并列，不再藏在「更多」菜单里
- **最近价时刻**：底部在只数后面给出这份行情的价格时刻（如 `4 只 · 14:02:31`）。优先用来源的成交时间，没给才退回取数时刻；列表取最旧的一份——多只里有一只停更，卡片上就有一只价格不能信；图形模式取图上最后一根的时间，与判陈旧同源，不会因为报价九拍才刷而假黄。超过三倍刷新间隔（下限两分钟）仍未更新就标一个告警圆点；收市与午休不标，那时的价格本来就不动。跨天补月日，避免隔夜后把昨天的收盘读成今天的
- **标记价提醒**：底部铃铛是开关，默认关，开启后由空心轮廓变为实心。现价上穿卖价、下穿成本时提醒一次；回到安全侧要再离开一个滞回幅度才重新武装，两次提醒之间还有五分钟冷却，阈值附近的抖动与来回穿越不会连环叫人。首次开启时按需申请浏览器通知权限
  - 装了 `@mzzsfy/dsh-turn-notify` 时交给它呈现：页内通知、提示音、系统弹窗与标题闪烁都按你在通知插件里的开关与专注静默走，不绕过；桥接版本对不上或调用抛错时退回本地降级，通道被你关掉时则保持安静
  - 没装时降级：悬浮窗闪一下、标题以 `🔔` 前缀闪烁（30 秒硬顶，窗口聚焦即停），有通知权限再发一条系统通知
  - 判定状态只在内存：刷新页面或重载插件后，如果价格仍停在触发侧，会再提醒一次；冷却也从重载后重新计时
- **悬停读出**：图形模式把鼠标移到分时上，给出该分钟的成交时间、价格与相对昨收的涨跌；指针在图区外就自动收起。列表模式悬停某一行，浮层给出当日最高/最低、今开/昨收与该股全部标记价——不用点进详情也能判断当天位置；浮层按条目数预估高度，行贴着窗口底部时翻到行上方，标记再多也不会被裁掉
- **右侧价格刻度**：图形右侧按可视最高最低画价格刻度，间隔取 `0.02 / 0.05 / 0.1 / 0.2 / 0.5 / 1 / 2 / 5 / 10 / 50 / 100 / 200 / 500` 的整档，个数控制在 2 到 4 个，每个价位配一个定位点，读得出价格对应哪一段走势；标签精度由步长决定，步长不小于 1 时不带小数。滚轮在图上下滚动缩放纵向范围（1 到 12 倍，切换标的自动复位），刻度随之重算；缩放以数据区间为中心，一字板或涨停横盘也不会把曲线挤出窗；横向比例不变
- **代码小字**：标题与列表每行在名称后补股票代码（11px、弱化色），同名或改过别名的标的也能认出来
- **图形先出图**：切到某只标的后第一拍直接拉分时，不再先刷一轮报价、让图空等一个刷新周期；这是"收市九拍静默"的唯一例外，代价是切标的期间多一次分时请求
- **图上的标记线**：落在可视区间里的成本/卖价画成常驻横线，超范围的不画、也不为它压缩纵轴；曲线下方另有一行完整标记清单，标出颜色与价位
- 与面板同步遵守涨跌配色（红涨绿跌 / 绿涨红跌）
- 勾选记录的 `ids` 有三种状态：缺省（从没勾过，退回自选前几只）、空数组（明确一只都不盯）、具体列表。0.3.1 之前的悬浮窗还没发布过，旧版本里 `ids: []` 表示"没勾过"，升级后会被读成"一只都不盯"，重新勾选一次即可

### 价格标记取代单值成本价

成本价只是一个特例：真正需要的是在图上标任意价格点位，并且每个都算盈亏。

- 每只自选可以挂最多 12 个价格标记，每条带语义：**成本**（持仓成本）或**卖价**（打算卖出的价），各自显示一个百分比
- 口径分开：成本标记显示「现价相对它」的浮盈，卖价标记显示「它相对成本均价」的潜在收益，还没有成本时退回相对现价
- 多笔成本按**等权平均**合成一个均价，列表的持仓盈亏与图表图例都用这个均价；单条成本标记显示它自己的浮盈。没有数量信息时，等权是唯一不引入臆测的口径
- 图上每条标记一条价格线，成本与卖价分色；辅助线菜单里的「成本价」改成「价格标记」，一次开关全部标记线
- 写入走单个 `marks` 操作做整组替换，增删改都是同一条路径，不会出现半更新的中间态
- 旧的单值成本已手工搬进标记列表，`cost` 字段从 schema 里彻底移除；未发版，不留迁移路径

### K 线指标与辅助线

- 新增 **EMA**、**BOLL**（中轨复用 MA20，上下轨为两倍标准差）、**BBI**（MA3/6/12/24 均值），与原有 MA5/10/20/60 一样可以单独开关
- 辅助线菜单分「参考位」与「指标线」两组：昨收、价格标记、区间最高/最低、MA、EMA、BOLL、BBI；四条参考线在价格轴上各有标签，指标线只出末值图例
- **图例分两区块**：第一行开/高/低/收/涨跌/量/成本盈亏（分时为最新/均价/昨收），第二行指标值，颜色与图上曲线一一对应；指标全关时第二行不渲染。成本属于报价要素，跟开高低收放一起，不再被指标挤到第三行
- 成本价线改为点线，不再压在图面上抢注意力；成本表单增加「清除成本」
- 日K 缺少昨收时，图例的涨跌退到前一根收盘，不再显示「—」
- 指标序列每次只算一遍：图例取末值、图上灌全序列共用同一份结果，不必为 9 条线重复走 4 次 MA
- **十字线读数**：鼠标移到 K 线上，光标旁给出那一根的日期、开高低收、涨跌与量；开着的辅助线（MA/EMA/BOLL/BBI）同步给出该根的数值，成对排列，关掉的线不列。日K的涨跌以它前一根收盘为基准，分时以当日昨收为基准；读数浮层贴在画布内，靠边时自动向内收

### 图表配色集中到 token

均线、布林、BBI、成本线的颜色原本散在 JS 与 CSS 两处各写一遍裸 hex，其中 MA60 与布林上下轨的灰度值饱和度只有两成，暗色主题下跟网格线几乎分不开。现在统一为包局部 token `--ssb-chart-*`，并按宿主写在 `body` 上的明暗标记给出两套取值：亮色取中低明度保证白底可辨，暗色整体提亮一档。宿主切主题或切涨跌配色时，蜡烛、成交量、均线一并重涂，不再只换背景。

“看得清”不靠肉眼判断：`test/chart-colors.test.mjs` 直接解析 token 声明，逐条算与主题底色的对比度（下限 2.5）、任意两条线之间的 CIELAB 色差（下限 12）与饱和度（下限 70%，低饱和的线在网格里同样认不出来），并要求暗色明度高于亮色。按这套尺子，原来有四个颜色在白底上不到 2.5：MA5 琥珀 2.06、MA60 青 2.32、BOLL 上轨 2.43、BBI 绿 2.43；色差一项旧值本就合格（最小 18.98），改色主要是为了对比度。

换肤不只在明暗之间发生：宿主把主题 token 内联写在 `body` 的 style 上，同色系两套主题或第三方主题覆盖 token 时 `data-ds-dark-theme` 并不变，只盯那个标记会整次漏掉。`body` 那路 observer 连 `style` 一起听，并先用取到的实际色值做签名比对，没变就不整图重涂——`body` 的 style 还会因字体、滚动条之类的无关变动抖动。

### 自选列表常显分组

- 置顶、各组、未分组各有段头，显示数量与组内涨跌统计，可折叠。此前只有「真的归了组」时才出段头，一只没归组时整页平铺，分组功能等于不可发现
- 分组与排序正交：全局排序不再丢弃分段，只决定组内顺序。此前切到涨幅/跌幅排序就整段跳过分组逻辑
- 组头用统一的 `head`/`section` 渲染，不再三处重复同一段代码
- 段头的折叠键加不可见前缀，且组名在服务端拒绝控制字符：组名来自用户输入，之前拿可输入的字符串当特殊键，用户建一个同名组就会跟置顶区互顶
- 折叠状态改由 `Object.hasOwn` 判定：直接按组名取属性时，`constructor`/`toString` 这类组名会读到原型链上的成员，整组被判成已折叠而不渲染

### 支持日经、韩证、伦敦

- 东财目录与搜索覆盖扩到八个市场，日韩英可直接「浏览市场」翻页、搜索添加
- 修正分时横轴：东财分时时间戳一律按北京时间给出（实测日股 `08:00` 对应东京开盘、英股 `16:00` 对应伦敦开盘），此前按市场时区解释导致日韩英横轴整体偏移数小时

### 显示偏好改存本地

悬浮窗位置与辅助线开关属于纯客户端显示状态，改为存浏览器本地，不再写宿主 `preferences`。这类开关每加一个都要改协议并重启宿主，收益不成比例。刷新间隔与涨跌配色仍留在宿主侧。

### 修复

- K 线缓存过期时把空值写回缓存表（`update` 不是删除），之后报价轮询遍历缓存遇到空记录直接抛 `Cannot read properties of undefined`，导致插件加载失败：改用 `delete`，遍历时跳过空记录，并声明无效记录备份后跳过——历史坏记录不再阻塞启动
- 沪深分时成交量未按手换算成股，导致分时图例的量比日K、详情小两个数量级
- 悬浮窗切换标的后，在请求返回前仍显示上一只的价格与分时
- 悬浮窗「打开详情」未清成本草稿，会把上一只的输入串写到另一只；面板不在前台时该按钮也没有反应
- K 线图与图例双数据源：手动刷新后图例、辅助线、指标线都已更新，蜡烛图仍是旧的；快速切周期时旧结果会覆盖新结果
- 悬浮窗在绿涨红跌配色下仍显示红涨绿跌
- 分时图例的「量」原取最后一分钟成交量，改为全天累计
- 缺失的行情字段被 `Number()` 变成真实的 0，区间最高/最低与迷你图因此被压到地板上；成本盈亏在缺收盘价时算出 −100%
- 成交量为 0 显示成破折号，与「成交额来源恒给 0」的缺失语义混在一起
- 悬浮窗拉取失败仍显示「监听中」，让人以为数据是新的；未勾选任何标的时也照样显示
- 同一标的连点刷新会并发两个请求，先发后到的响应会把新数据盖掉
- 悬浮窗拖动不区分按键，右键也会拖动；拖动时列表与勾选区无法用触摸滚动
- 图表背景一直是透明的，而图表容器自身没有底色，暗色主题下整块图表区露白
- 主题或涨跌配色切换后，蜡烛、成交量、均线从未真正重涂过：重涂回调跑在空依赖的 effect 里，读到的是首帧那份空数据与旧配色
- 数据先于建图到达时（补灌路径），指标线被清成空，图例有值而图上没有线
- 悬浮窗「全部收市降频」不生效：读的是 `quotes[id].sessionState`，实际在 `quotes[id].quote` 里，于是收盘后仍按交易频率拉取
- 同一标的连点刷新时，被淘汰的旧请求若失败，仍会把错误写进去并清掉新请求已落地的数据
- 顶部「刷新」把 React 的点击事件当成证券列表发出去，序列化时撞上循环引用，页面顶部常驻一条红色错误；错误又被统一捕获吞掉，表现为「点了没反应」
- 分时均价线恒等于收盘线：数据清洗只保留固定的几个价格字段，东财分时第 8 列的均价被整体丢弃
- 一根缺 `close` 的分时蜡烛会让其后全部 MA/EMA/BOLL/BBI 变成 `NaN`，右侧指标线整段消失；NaN 还会穿透图例的 `== null` 守卫直接显示「NaN」
- 悬浮窗图形模式收市后仍按刷新间隔打分时接口，而该接口不进缓存（每拍都是真上游）；收市判断又读面板那份报价，面板不在前台时会一直停在交易时段上，连降频都不触发
- 同色系两套主题或第三方主题覆盖 token 时图表不重涂：`body` 的 observer 只听明暗标记，而宿主把 token 内联写在 `style` 上
- 浏览页指数概览条在缺 `previousClose` 时渲染出「+null（+null%）」

### 探针从「闸门」改成「诊断」

此前保存配置要求每个目标都有未过期的探针通过记录，没检查过就存不进去。这把事情搞反了：探针是给人看的信息，不是准入门槛。数据源挂了不代表你配错了，想先存下来待会再调也不行。

- 保存只看配置自身是否合法（路由引用的实例存在且已启用、能力匹配），不再要求任何 checkId
- 每个能力格子里有独立的「测试」按钮：点一次只探这一条路由，回报成功/失败与端到端耗时，例如 `✓ 128ms`
- 「全部测一次」保留，结果同样只是展示
- 探针耗时就是真实取一次数据的往返时间，单位毫秒，失败时悬停看错误码与原因
- 「应用推荐配置」与「一键补全」仍然自带体检并把不可用的目标剔除，那是推荐配置的质量保证，和手动保存是两条路

### 设置页改摘要优先

设置页此前按数据结构铺开：数据源页每个实例一张全展开的卡片，市场与能力页 8 个市场各 4 到 5 个下拉框，一共 34 个下拉平铺两屏。99% 的时候这些字段不需要动，需要动的时候又得在 34 个框里找。

```
港    XHKG   东财 · 目录/搜索/报价/K线        备 新浪/腾讯   改
```

- 摘要行直接回答「这个市场用什么源、备源是谁」，鼠标悬停给出逐项分配
- 数据源行回答「这个源在干什么」（几条路由、几个市场、哪些能力），适配器描述移到展开区外常驻一行
- 能力名按固定顺序呈现，不再跟随内部数组顺序
- 设置弹窗高度从 1561px 降到 743px，一屏装得下八市场
