# dsh-turn-notify 兼容性测试

包定位:会话轮次结束通知(设置「消息通知」节 + webhook host 直发)。host 半区观察 `session/event` 与 `approval/request`,把回合结果归入六类(任务完成/任务出错/被中断/等待审批/AI 提问/达到上限),按事件→通道路由(kindRoutes)送达七通道:`sound`/`system`/`toast`/`blink`/`webhook`/`im`/`host`(页内提示音为 toast 衍生通道)。webhook、IM、宿主桌面通知由 host 直发(超时 10 秒,fire-and-forget);浏览器通道经内存投影(环形 20 条/60 秒过期,不落盘)由 client 长轮询取用,localStorage 认领锁保证多窗口只响一次。设置面为 settings.section 分区「消息通知」(order 41,settings 命名空间 `turn-notify`),client 经 10 条 `/api/turn-notify/*` 路由读写配置、音效库与测试点火。独立功能面二件:会话行高亮(tn-sess-hl 六分类色脉冲)与工作区文件夹运行标记(自 session-manager 迁入,已确证,见断言 #7)。

### L2 装载层

- 冒烟覆盖:scripts/smoke-load.mjs 遍历 packages/ 全部含 package.json 的包并动态 import 各包 main(本包 src/index.js),本包在清单内:顶层依赖 `@deepseek-ai/schemastery` 缺失或模块级错误当场 FAIL(其余顶层 import 均为 node 内置模块);支持 --profile 测 profile 安装副本。src/client.js 非 main 不被该脚本 import,其装载由本层 boot 判据与 L1 的 parity/flow/hmr-heal/switch-guard/client-id 源码级测试覆盖。
- 隔离环境 boot 判据:bundle 经 `dsh plugin add @mzzsfy/dsh-turn-notify` 注入 profile(cordis.patch.yml 单行 insert,id=turn-notify,无 dsh-toast 占位行)后重启一次宿主完成首装载;判据 = activation live + diagnostics findings 0 + 页面无 `Failed to load plugins` + `GET /api/turn-notify/config` 返回 200 且响应含 `folderRunningEnabled` 字段(顺带确证运行标记配置面 host 侧可用)。
- 干净禁用形态:顶层 `inject = ['webServer']` 点分声明,宿主缺 webServer 时 fiber 不激活即整体干净禁用,不 pending 拖死 boot;settings 经 `ctx.inject(['settings'], ...)` 嵌套声明,缺失时仅跳过设置节注册,事件观察与路由照常;可选依赖全部运行期探测——dshIm 经 `ctx.get('dshIm')`(IM 通道静默弃投)、session-title 服务(标题回落首条消息)、`@mzzsfy/dsh-toast/client` 经 try require(页内提示通道干净禁用,其余通道不受影响)。任一可选依赖缺失均不判失败。
- 环境副作用:音效库目录 `~/.dsh/dsh-turn-notify/sounds` 惰性创建,投影不落盘;本流程测试全程只读,不产生宿主侧数据(唯一写面是浏览器 localStorage 本机键与误触测试按钮的外发,后者被专项注意禁止)。

## L4 共存层

- @mzzsfy/dsh-toast(公共依赖,package.json 显式 dependencies):模块表挂载由 session-manager 唯一代挂,本包 client 经 try require 可选消费。「在场/缺失」两形态均合法:在场时操作反馈与页内通知走 toast 浮条,缺失时反馈降级 console.warn、页内通道禁用而其余通道照常;均不判失败。同装验证两形态下面板与通知链路互不干扰。
- session-manager(服务快照消费):本包 client `inject = ['slots', 'sessions', 'workspaces']`,运行标记投影只读 `sessions.list` / `workspaces.list` 快照;会话行高亮为纯 DOM 标题匹配观测;两者均不写入任何服务状态;slots 注册 id=turn-notify、order 41 与其他分区无冲突。同装时验证侧边栏分组模式下运行标记与 session-manager 自身 UI 不互相覆盖。
- dsh-im(IM 通道,可选):运行期 `ctx.get('dshIm')` 探测,imAvailable 决定 IM 分区与测试按钮(#10);bot 离线时通知弃置不补发,不影响其余通道。
- @deepseek-ai/dsh-session-title(peer 依赖,可选):服务在场时会话标题与侧边栏行同源,缺失回落首条消息文本,均不判失败。
- dsh-settings-nav-icons(导航图标):client 半区声明双键 `{ '消息通知': 'bell', 'dsh-turn-notify': 'bell' }`,经 `window.__navicIcons.register` 注册或 `__navicIconQueue` 入队(本插件先于其就绪时入队,由其启动排空)。同装时验证设置导航「消息通知」项带铃铛图标;该插件缺失时仅图标不渲染,分区仍可点,不判失败。
- 独占命名面:settings 命名空间 `turn-notify`、10 条 `/api/turn-notify/*` 路由、localStorage 键 `turn-notify:` 前缀、样式注入 data-plugin=`@mzzsfy/dsh-turn-notify`(flow 测试锁定,防宿主 claimStyles 误归属后随其他插件 HMR 整批误删),全家桶下无注册冲突;任意其他插件 HMR 重建后本包面板样式不得丢失(丢失表现为控件裸排)。
- 共存底线:任意插件组合下页面无 `Failed to load plugins`;全家桶共启后本包 activation live、diagnostics findings 0。

## 专项注意

- **测试点火按钮一律不点**(保留并强化原 webhook 约定,逐个点名与原因):
  - 「测试 webhook」:向已保存 URL **真实外发 HTTP**(原约定);未配置时虽只报错,但保持一律不点。
  - 「测试 IM 通知」:向全部已配置目标**真实外发 IM 消息**。
  - 「测试宿主通知」:宿主进程 **真实弹 OS 桌面通知**(spawn powershell/osascript)。
  - 「测试系统通知」:5 秒倒计时后**真实弹系统通知**,且未授权时会先触发浏览器授权流程。
  - 「测试声音」与各「试听」:播放声音,依赖浏览器音频放行徒增浮动,不点。
  - 「授权」按钮:触发浏览器权限弹窗阻塞自动化,不点。
- **一切写操作不做**:「保存」「清除」按钮、全部 `.tn-switch` 开关与 `.tn-pill`(点击即存,立即 POST config 污染宿主配置)、映射 select、上传/删除/重命名。运行标记开关切换后配置即改且刷新页面才生效,测试不切换;测试结束面板应保持默认态。
- 环境前提:隔离宿主经 `dsh plugin add @mzzsfy/dsh-turn-notify` 注入并重启完成首装载;宿主须提供 webServer(顶层 inject,缺失即插件整体不激活)。无数据目录环境变量前提:音效库目录惰性创建且本流程全程只读,不产生宿主侧数据。
