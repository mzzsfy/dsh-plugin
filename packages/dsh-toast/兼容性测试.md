# dsh-toast 兼容性测试

包定位:公共 client 依赖包(全局浮出通知 Toast 库,store + 渲染组件),普通 npm 依赖形态,无 bundle patch、无独立 UI 格、无服务面。**不单独成格测试**,由消费方代挂覆盖。

## 测试分层与执行流程

| 层 | 内容 | 手段 |
|---|---|---|
| L1 单元层 | store 行为、挂载自愈、自注册格式守卫、公共依赖包形态守卫(4 文件 35 用例) | 包目录 `node --test "test/*.test.mjs"` |
| L2 装载层 | 宿主入口可加载;占位条目激活与模块表物化前提 | 仓库根 `node scripts/smoke-load.mjs`;隔离 profile 启动 |
| L3 功能面层 | 无独立格,由消费包兼容性格代挂覆盖 | 各消费包 playwright 格,按覆盖矩阵核对 |
| L4 共存层 | 全家桶共启,真实触发 toast 的渲染探针 | 浏览器 DOM 探针,挂任一消费包 playwright 会话执行 |

执行顺序:L1 → L2 → L3 → L4,前层失败即止。

### L1 单元层

其中 3 个文件(client-id / toast / mount)以 `new Function` 加载真实 `src/client.js`(注入 window/require/document stub,mount.test.mjs 另注入 console 捕获告警),react 为 stub:覆盖 store 与 DOM 交互路径,不执行真实 React 渲染(归 L4 探针)。`toast.test.mjs` 与 `mount.test.mjs` 以 `mock.timers` 冻结 setTimeout,手动推进验证展示期。manifest-form.test.mjs 为静态形态守卫,只读 package.json 与本机 profile manifest,不加载 client.js。命令在包目录执行:`node --test "test/*.test.mjs"`(等价 npm test)。

| 文件 | 用例数 | 覆盖点 |
|---|---|---|

### L2 装载层

装载链背景(内联):本包不声明 `dsh.bundle.patch`、不自带 cordis.patch.yml、不进 profile 表层 manifest 依赖行。安装与解析链:消费插件在 package.json `dependencies` 声明本包 → pnpm(hoisted 布局)把传递依赖实体安装到 profile 顶层 node_modules,解析天然可达;开发态 dev-link 的 junction 覆盖同一路径指向仓库工作副本保热更;dsh 启动时内置 fallback 沿 bundles 依赖闭包补链顶层缺失的包作兜底(对既有链接跳过不替换,卸载最后消费方后自动清理)。装载链:占位消费包 cordis.patch.yml 的 insert 列表追加宿主占位条目(id 带消费包前缀,`name` 为 `@mzzsfy/dsh-toast`,name 才是包解析键)→ cordis loader 装载占位条目,经裸名 id 从模块表取记录激活空 apply 宿主半区 → 宿主 client-modules 按 npm 名解析包、读 `dsh.client` 声明,把 `src/client.js`(以 `__ModuleLoader__.load({id:'@mzzsfy/dsh-toast', factory})` 自注册)物化进客户端模块表 → 消费包 factory 内 `require('@mzzsfy/dsh-toast/client')` 取得 show/dismiss/mount。

- `node scripts/smoke-load.mjs`:脚本无硬编码清单,枚举 packages/(或 `--profile` 时 profile 顶层 node_modules/@mzzsfy)下所有含 package.json 的目录——目录与符号链接(junction 在 Dirent 上呈 symlink)都收,逐个动态 import main;main 入口缺失的包输出 SKIP、不计失败。本包自动在内,预期出现包名为 `@mzzsfy/dsh-toast` 的 OK 行(实际输出为 `OK   包名`,OK 后三空格等宽对齐,勿按单空格子串匹配);main 为空 apply 宿主入口,此层验证 ESM 可解析、导出形态合法。`--profile` 变体对本包即验证「传递依赖落顶层 / junction / fallback 补链」三者之一的解析可达性,是空窗形态的检出手段。
- 隔离环境 boot 判据:隔离 profile 安装至少一个占位消费包(session-manager 或 context-manager,见覆盖矩阵)且其存在于 `dsh.profile.bundles`,启动后:占位条目(`session-manager-dsh-toast` / `context-manager-dsh-toast`)装载无 invalid plugin 报错、页面无 `Failed to load plugins`、diagnostics findings 0、消费包与本包占位均 activation live。占位宿主半区为空 apply,无独立可观察 UI,其「live」以启动无错 + findings 0 为证。

### L3 功能面层

本包无独立格,由消费方代挂覆盖,间接覆盖机制分两半:

- 装载覆盖:只有权威消费方 session-manager 能证明物化——其 client.js 在 factory 顶层直接 `require('@mzzsfy/dsh-toast/client')`,模块表缺失即其自身 client 失败,故 session-manager 的 L3 通过 = 模块表已物化本包 client。其余 5 包为 try/catch 可选 require,降级后 factory 照常成功,它们的 L3 通过不构成物化证据,仅证明其自身功能正常。
- 运行覆盖:消费包格内凡触达操作反馈的流程(保存、归档、升级类动作)会真实调用 show,但各包 L3 断言不锚定 toast 渲染本体,渲染证据由 L4 探针出具。
- 判定:全部 6 个消费包各自 L3 通过 = 本包装载与运行调用路径通过(渲染证据由 L4 出具)。物化证明由 session-manager 一家承载;降级形态的运行证据不依赖消费包单测——逐包核实,仅 model-capability-editor 单测显式覆盖降级(模拟依赖在/不在模块表两种宿主形态),turn-notify 与 context-manager 的单测仅 mock 在场形态,maintain 与 usage-panel 单测零引用本包;可选消费方「缺失干净降级」在真实宿主中的证据由 L2 boot 判据与 L4 探针暴露。

### L4 共存层

全家桶共启(全部消费包同一 profile 安装并激活),渲染探针在任一消费包的 playwright 会话内执行,无独立格:

| # | 探针 | 预期 |
|---|---|---|
| 1 | 消费包触发 toast(如 maintain 升级反馈、session-manager 归档反馈)后取 `document.getElementById('dsh-toast-host')` | 非 null,内含 `.dsh-toast-stack`,条目元素带 `role="alert"` |
| 2 | `document.getElementById('dsh-toast-style')` | 在 head 且 `getAttribute('data-plugin') === '@mzzsfy/dsh-toast'`(防宿主 claimStyles 误归属误删的契约) |
| 3 | 非 sticky 条目等 4 秒后复测 | 条目自动移除;sticky 条目常驻且带「知道了」按钮 |
| 4 | 打开设置全屏层后触发 toast | toast 可见(z-index 1100 为对宿主层级的显式假设,宿主层级调整时的回归点) |
| 5 | 开发态 HMR 重载后由消费包再触发 | 新代容器接管、渲染正常;出现一次「已退役」console.warn 属设计行为(旧代迟到通知不可见,刷新页面恢复) |

## 专项注意

- 危险操作:无。本包无服务面、无文件与网络副作用。测试过程禁止手动增删 `dsh-toast-host` / `dsh-toast-style` 节点制造场景(自愈路径已由 L1 用 stub document 覆盖),避免假阳性与页面残留。
- 环境前提:Node >= 22(engines 声明);react 与 react-dom/client 由宿主平台模块表提供;隔离 profile 必须含至少一个占位消费包且其在 bundles 内。全部消费方都退出 bundles 时,占位条目与 fallback 补链闭包同时消失,模块表不物化,全部可选消费方静默降级、toast 通道整体下线——这是已知空窗形态,不是本包缺陷。
- 误判防范:
  1. 归因规则:单个消费包失败且其余通过 → 消费包自身问题,不回溯本包;两个及以上消费包同报 toast 相关错误(模块表缺 `@mzzsfy/dsh-toast/client`、invalid plugin 指向 dsh-toast、占位条目装载失败)→ 回溯本包,按 L1 → L2 复查。
  2. 可选消费方静默降级不是故障:模块表缺失时其 toast 通道干净禁用,console 无 toast 输出是预期;判别依据是「模块表是否物化本包」,不是「消费包是否报错」。
  3. 设计内告警不判故障:「本代已退役」(HMR 旧代闭包迟到通知,一次性,刷新恢复)与「容器挂载失败」(单次 warn,条目仍在 store,下次 show 自愈重建)均为 console.warn 级自愈行为。
  4. 双占位并存:session-manager 与 context-manager 当前各带一条占位条目,装载基一致(同为 profile 根)时模块表多源检查通过;装载基不同(如一方经市场 .dsh-market 托管、一方为 profile junction)时判 fatal,整树 `Failed to load plugins`——报错主体是 toast 占位条目,归因是消费包安装来源不一致,对齐安装来源即解,不是本包缺陷。包内其他文档「占位条目全仓唯一(当前为 session-manager)」的表述已与仓库现状漂移,以本矩阵实测为准,漂移应报对应包维护者修正。
  5. React 版本漂移:L1 以 stub 驱动、不执行真实 React,宿主平台 react 大版本变更(useSyncExternalStore / createRoot 行为差异)只能由 L4 渲染探针暴露,宿主升级后不得跳过 L4。

## 判据

统一底线:activation live + diagnostics findings 0 + 页面无 `Failed to load plugins`。观察来源:dsh 网页 GUI——插件面板看各包 activation 为 live,诊断面板看 findings 计数为 0,页面顶栏看无加载失败横幅;L2 隔离 boot 与 L4 全家桶同源观察。

1. L1:包目录 `node --test "test/*.test.mjs"` 全过(4 文件 35 用例,0 fail;无本机 profile 时 manifest-form 后 2 例 skip,skip 不计失败)
2. L2:仓库根 `node scripts/smoke-load.mjs` 输出含包名为 `@mzzsfy/dsh-toast` 的 OK 行且 0 个 FAIL 涉本包;`--profile` 形态同过(安装副本解析可达)
3. L2:隔离 boot 满足 L2 节 boot 判据(占位条目激活无 invalid plugin + 统一底线三项)
4. L3:6 个消费包各自兼容性格(playwright)全部通过
5. L4:渲染探针 5 项全过
6. 归溯:单消费包失败归消费包自身;多消费包同报 toast 错误 → 回溯本包重走 L1 → L2

以上 1 至 5 全部满足且符合统一底线,本包兼容性判定为通过;第 6 条是失败时的归因路径,不是通过条件。
