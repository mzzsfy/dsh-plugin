# dsh-common-tools 兼容性测试

本包是普通 npm 依赖，不是 DSH 插件。两端 `setupCommonTools(ctx)` 自动以 loader 完整 npm 包名绑定空间，提供 `subscribe(listener)` / `publish(payload)`。host 额外提供 onPresence，client 可在 subscribe 的第二参数设置 onReset。插件就是通道，无 topic 或消息版本。

在本包目录执行 `npm install --omit=peer` 后运行 `node --test "test/*.test.mjs"`。

## 有头浏览器验收

以下是总线夹具验收规格，执行者需建立随机端口隔离夹具加载真实host/client。禁止改生产profile或重启生产宿主；夹具本身不涉及LLM。完整宿主端到端验收须另建隔离profile，涉及真实回合时只使用本轮新起的 echo-upstream。

| Given | When | Then |
|---|---|---|
| 亮色或深色宿主主题 | 以 toast/panel 两种 appearance 分别弹 info/ok/error 与 sticky 通知 | 正文/多行小结/关闭按钮对比度至少 4.5:1；状态仅改变边框，关闭按钮正常 |
| 两种样式通知仍在位 | 切换宿主主题 | 底色与文字成对更新，无固定色残留 |
| 两插件通道已订阅 | 分别发送相同JSON | 仅对应空间收到，共用一条WS |
| 纯发送实例已连接 | 不订阅直接publish | 仅对应host收到，presence仍为零 |
| 页面空闲 | 观察Network至少跨过一次心跳 | 无周期HTTP快照或持续重连 |
| 多实例/多接收空间 | 部分退订 | WS保持，仅相应接收presence减少 |
| 所有组件已退订 | 实例仍在 | 仍可发送 |
| 所有client实例卸载 | 等待关闭 | WS归零，不再重连 |
| 连接中断 | 重新收到ready | onReset拉快照，断线写不重放 |
| 快照响应很快 | 持续发布失效通知 | 宿主合并广播；同源快照请求start间隔至少一秒，末轮状态收敛 |
| 快照被挂起 | 连续变更后释放响应 | 单飞，仅保留待刷新状态；后续请求受时间窗约束，最终状态收敛 |
| 刷新在途或定时待发 | 最后实例卸载 | 取消待发刷新；在途请求中止或迟到结果被忽略，不重新挂载 |

## 本轮功能复验

2026-10-23 在同一隔离宿主版本复验最终实际安装实体：common 与五消费方共 944 项测试连续三轮通过，15 个关键文件与源码一致，七包宿主入口可加载。真实有头页面的双向中文 JSON、插件隔离、纯发送、1000 条业务消息顺序、双窗通知、断线/503/迟到快照恢复、42 次官方启停、cron 真实调度与会话投递、tunnel HTTP/WS、若水两步执行与取消删除通过。快响应三轮各 20 次变更对应 8/9/9 次快照，页面 fetch 起始最短间隔 1000.5/1000.4/1002.7ms；挂起期间 31 次变更并发峰值 1，最终版本收敛。

源码 watcher 热重载检查未通过：服务 active 且实际 watched 含源码，但修改后的标记与临时路由未观测到生效，原因未定。此项与官方启停、单元测试的代际回收分别记账。外部 IM/webhook、物理声音/桌面通知、若水完整暂停审批续跑矩阵及其他宿主版本未扩测。最终矩阵、失败原件与两次进程/端口清理结果保存在本地 `.compat/ws-surfaces-20261023/REPORT.md`、同目录 `coverage.json` 与 `cleanup.json`；不将未通过或未测项计入通过。

## 装载与边界

client由每个消费插件自带的一行装载行引入(消费方`cordis.patch.yml`内`id:<本包前缀>-dsh-common-tools`、`name:'@mzzsfy/dsh-common-tools'`),宿主按包名把多行合并成一份client模块,装任一消费插件即可独立运行;消费方另声明`^0.4.0`依赖与external `@mzzsfy/dsh-common-tools/client`。setup在apply(ctx)执行;订阅归属该实例,组件可提前退订。host缺registerUpgrade时告警停用,不注册资源。空间是路由边界,身份与信任由宿主承担。0.4.x只准发patch,0.5.0须与十个消费方范围抬升同批;hello协商与降级路径见README「兼容窗口与版本协商」。

0.2.0为破坏性变更，无旧SSE或topic接口兼容层。升级须统一更新两端与消费方、完整重启宿主并刷新旧页面；0.1与0.2同进程混装会发生注册表冲突，不支持跨代际热接管。真实WS薄宿主测试和上述浏览器夹具不能替代仓库compat完整隔离profile boot或逐版本兼容性结论。

(随包 0.2.1 发布)2026-10-23 在隔离 DSH 0.2.1-rc.2 完整宿主与有头 Chrome 验证：真实 pnpm 升级的 hoisted 安装实体冷启动，session-manager 与五消费方全部 live、diagnostics findings 为零；五空间业务推送、断线快照恢复、空闲跨心跳、官方插件启停与最后实例关闭通过。实机发现并修复 turn-notify 投影路由卸载遗漏，重新打包安装后冷启动复验 turn-notify 三轮启停及五插件全停全启通过。isolated 与 hoisted 两种 pnpm 依赖升级均解析 common 1.0.0(当日本地工作副本身份,该版本号未发布上线,后降为 0.2.0)。此结论仅覆盖本轮 WS 链路与该宿主版本，不表示全版本或所有业务功能兼容；最终证据为本地 `.compat/ws-e2e-20261023/final-evidence.json`，独立有头网络与控制台记录为同目录 `headed-check.json`；升级报告与混装结果分别为 `.compat/ws-upgrade-20261023/REPORT.md`、同目录 `mixed-version-result.json`。早轮 `snapshot-evidence.json` 仅记录快照阶段，最终结果以 `final-evidence.json` 为准。

## 维度检查点(补充)

### 代际与升级(D06)

1. 0.1 与 0.2 同进程混装 → 注册表冲突或明确拒绝,不静默半工作;该形态不支持,不得作为兼容目标。
2. 升级路径:统一更新两端依赖 + 完整重启宿主 + 刷新旧页面;旧页面残留旧代际时必须失效而非串协议。
3. 代际回收:HMR 后旧 factory 的定时器/订阅/连接全部释放,新代际接管。

### 连接与快照(D07/D13)

4. 八实例反复启停五轮(既有用例),真实 WS 峰值恒为 1;HTTP 快照正常;最后实例卸载后连接归零、不再重连;当前 10 个消费方全家桶共启另验。
5. 失效通知合并广播;同源快照请求起始间隔 ≥1s;挂起期间单飞,释放后只保留待刷新状态并最终收敛。
6. 断线重连收到 `ready` 后 `onReset` 拉快照;断线期间的业务写不重放(避免重复执行)。
7. 最后实例卸载时取消待发刷新、中止在途请求或忽略迟到结果,不重新挂载。

### 跨源与身份(D12)

8. 跨源写请求被拒绝;无 Origin 的同源/非浏览器请求按既有契约处理。
9. 通道身份取 `ctx.fiber.entry.options.name` 完整包名;显示名/短名不得作为身份。
10. 不同插件空间同名 payload 不串;纯发送实例不产生 presence。

### 呈现(D14)

11. 亮色/暗色宿主主题下,toast 的正文、多行小结、关闭按钮对比度至少 4.5:1;状态只改边框。
12. 两种 appearance 分别覆盖 info/ok/error 与 sticky;切换主题后底色与文字成对更新,无固定色残留。

## 判据补充

上述补充检查点与既有无头/有头验收全部通过才可宣称本代际兼容;0.1 旧页面、混装、未重启升级一律记不通过。历史记录中的 `.compat/ws-*` 证据只对当轮宿主版本有效,跨窗口复用须重跑。
