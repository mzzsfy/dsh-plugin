# 多 cron 计划 BDD

本文件描述 dsh-cron-board「一条任务挂多条 cron 表达式」的行为契约。实现面:`src/cron.mjs`(计划文本解析/合并触发点/摘要/校验)、`src/scheduler.mjs`(调度与恢复)、`src/api.mjs`(落库与预览)、`src/client.js`(计划行列表)。

## 背景

同一任务常有多个触发时刻(工作日 09:00 与周末 10:00、每天两次巡检、每小时一次加每天汇总),此前的做法是建多条任务,导致同名任务分散、运行记录与日志割裂、启停要逐条操作。crontab 本身用多行表达多计划,本插件沿用同一模型。

## 模型决策

计划仍是任务行上的一个 `schedule` 字符串,多条表达式以换行分隔;不改成 `schedules: string[]` 字段,理由:

- 语义单位是「任务的触发时刻集合」,不是带 id 的实体;数组只增加 CAS、脏字段比对、持久化迁移与双字段兼容的成本。
- 换行文本与 crontab 同构,导入/导出/手工编辑直接可用;表达式本身不含换行,拆分无歧义。
- 存量数据零迁移:单条表达式的任务行形态不变,读写路径不出现 `schedule`/`schedules` 双分支。
- 归因是记录字段而非任务结构:运行记录新增 `schedules`(命中的表达式原文),不拆 `schedule` 字段、不引入每表达式状态。

归一规则:行首尾空白去除、空行丢弃、重复行丢弃并保持书写顺序。上限 10 条(`MAX_SCHEDULES`,防误贴长文本放大 tick 计算量)。

## 调度语义

- `nextRunAt` = 各表达式自当前时刻起的下一次触发中的最早值;落库仍是单值,不引入每表达式状态。
- 同刻命中多条表达式(含不同时区换算到同一瞬时)合并为一次运行:一次 tick 只预占一次执行,`runOnce` 任务一次运行即停用。
- tick 推进:取合并后的最早触发;到期时按该瞬时命中哪些表达式写运行记录 `schedules`(S9)。
- 恢复自愈:`nextRunAt` 属于任一表达式的合法触发点即保留(DST 映射判定同样逐条进行),否则重算为合并后的最早触发。
- misfire:到期值早于当前超过一个 tick 周期即记 `skipped` 并推进,多条表达式不改变该语义。

## 场景

### S1 计划文本归一

- Given 表单或 API 提交 `"  0 9 * * *  \n\n0 9 * * *\n30 8 * * *\n"`
- When 服务端归一
- Then 落库与摘要只含两条表达式,顺序按书写;重复行与空行不产生额外触发点

### S2 合并触发点

- Given 计划为 `0 9 * * *T+8` 与 `30 8 * * *T+0`
- When 求下一次触发
- Then 取两者中更早的瞬时;单条计划的结果与标量求值逐值一致;空计划无触发点

### S3 合并预览

- Given 编辑表单存在两条以上计划行
- When 请求 `POST /api/cron-board/cron/preview`
- Then 返回 `items`(逐条表达式、摘要、三次触发点;重复表达式按落库口径去重)以及合并 `summary` 与合并 `nextAt`(升序去重);表单按规范化后的表达式文本匹配行(存量 `T+8` 带空格等书写差异也能对上),只把命中条目的 `nextAt` 显示为该行的「即将执行」

### S4 逐条校验

- Given 计划中任意一条表达式非法,或任一条合法但永无未来触发点
- When 新建任务或修改计划
- Then 400,文案带该行原文(不静默丢弃该行、不只校验第一条);空计划回「调度计划不能为空」;超过上限回「最多 N 条表达式」;仅改名/启停/并发等维护性 PATCH 不触发计划校验

### S5 调度合并与推进

- Given 计划为 `* * * * *` 与 `0 0 1 1 *`,到期值取更早的一条
- When tick
- Then 只预占一次运行;推进后的 `nextRunAt` 是两条表达式合并后的最早触发(每分钟那条),不是一年后那条
- And 运行记录的 `schedules` 只列命中该瞬时的表达式(此例仅每分钟那条)

### S6 恢复自愈

- Given `nextRunAt` 只落在计划中第二条表达式的触发点上
- When 重启恢复
- Then 保留该值(不因第一条表达式不是触发点而重算);`nextRunAt` 不属于任一条表达式的触发点时重算为合并后的最早值

### S7 展示

- Given 任务有多条计划
- When 列出任务
- Then 任务卡摘要逐条以 ` · ` 连接;`nextRunAt` 展示合并后的最早触发
- And 日志 Tab 的展示时区在全部计划行时区一致时取该偏移,混合时区回退宿主默认
- And 运行行在触发标记后展示该次命中的计划摘要(服务端派生 `scheduleSummary`,原文在 `schedules` 供悬浮查看)

### S8 编辑面

- Given 已存在任务(单条或多条计划)
- When 打开编辑器
- Then 计划行列表逐条显示摘要,「+ 添加时间」追加一行,行尾「删除」移除该行(最后一条不可删除);选中行在下方构建器编辑;保存只提交相对打开时快照有变化的字段与 `updatedAt` 基线

### S9 逐表达式归因

- Given 计划两条表达式在同一瞬时命中(如 `0 9 * * *T+0` 与 `0 1 * * *T-8`)
- When tick 触发该任务
- Then 运行记录带 `schedules`(命中的表达式原文,按书写顺序,重复行去重);`GET /api/cron-board/runs` 派生 `scheduleSummary`(逐条摘要 ` · ` 连接);手动触发不带该字段
- And 同刻只产生一条运行记录:归因是记录字段,不拆分运行
- And misfire `skipped` 与 dispatch 失败 `fail` 记录同样带归因,便于定位是哪个计划被错过/失败

## 不做

- 不按表达式拆分运行记录:同刻仍合并一次运行,`schedules` 只是归因字段;`trigger` 仍只有 `cron` / `manual`。
- 不为每条表达式提供独立启停、独立时区展示或独立并发语义:它们属于同一任务,共享任务级配置。
- 不改变宿主「自动化任务」(`dsh-schedule`)的数据形态:那是另一数据源,由宿主管辖。
