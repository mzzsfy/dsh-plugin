# dsh-cron-board 兼容性测试

包定位:侧栏「定时任务」面板,任务列表与新建/编辑 UI(调度执行依赖宿主 timer 服务,软依赖)。面板含「看板/环境变量/日志」三个 Tab;执行体两类:本地脚本(宿主进程内 spawn)与会话任务(定时向 dsh 会话投递,投递即终态)。会话任务另依赖宿主 sessionController 服务:插件启动后异步轮询等待 15 秒,仍缺失即干净禁用该通道(脚本任务不受影响),不阻塞 boot。

## 测试分层与执行流程

| 层 | 内容 | 手段 |
|---|------|------|
| L1 单元层 | test/ 下 13 个 `*.test.mjs`,覆盖装配/持久化/执行链/调度/会话编排/路由/构建器/双实现同源/客户端结构守卫(清单见下) | 包目录 `node --test "test/*.test.mjs"` |
| L2 装载层 | 全包冒烟加载 + 隔离宿主 boot 干净禁用判据 | 仓库根 `node scripts/smoke-load.mjs`(本包在清单内)+ 隔离 profile 启动(必带 `DSH_CRON_BOARD_DATA_DIR`) |
| L3 功能面层 | 基础面 4 项 + 侧边栏联动 10 项(即下节断言全集) | playwright 页面断言(隔离宿主) |
| L4 共存层 | 与 better-sidebar(开关依赖)、turn-notify(定时轮询类共存)、dsh-settings-nav-icons(导航图标)等全家桶交叉 | 同装验证 + 页面级回归 |

执行顺序 L1 → L2 → L3 → L4,前层失败即止。

### L2 装载层

- 冒烟覆盖:scripts/smoke-load.mjs 遍历 packages/ 全部含 package.json 的包并 dynamic import 其 main(本包 src/index.js),本包在清单内;croner 依赖缺失或宿主半区命名导出缺失当场暴露。支持 --profile 测 profile 安装副本。
- 隔离环境 boot 判据:bundle 经 dsh plugin add 注入后需重启一次宿主完成首装载;判据 = activation live + diagnostics findings 0 + 页面无 `Failed to load plugins` + `/api/cron-board/status` 返回 200 且 timerRunning 字段如实反映宿主 timer 在场。本包 inject 仅声明 webServer,旧宿主(如 0.1.1-rc.2)缺 sessionController 不会 pending 拖死 boot:启动后异步轮询等待 15 秒,仍缺失即干净禁用会话通道并打日志,路由与脚本任务照常服务。
- 启动隔离宿主必须带 `DSH_CRON_BOARD_DATA_DIR=<临时目录>`:不设则数据目录落到默认 `~/.dsh/cron-board`,与生产实例共用同一目录,测试新建/启停的任务会被生产实例的调度器拾取真实执行(测试不是只读操作)。env 覆盖逻辑有单元测试锁定(空白值不生效,回默认)。

### L4 共存层

- better-sidebar(开关依赖):client 半区经 `ctx.get('betterSidebar')` 软探测,服务在场才可切换,不在场开关禁用仅展示(干净禁用,无副作用)。本包 node_modules 不含 dsh-better-sidebar(已核实,仅 croner),它以宿主侧插件服务形态在场,包级安装不会引入;「在/不在」两种 bundles 形态都必须测。
- turn-notify(定时轮询类共存):两插件同用宿主 timer 服务,各自独立 interval 互不接管;本包以全局并发闸门(默认 2)与任务级并发上限约束自身执行单元,不独占宿主资源。同装时验证两者 activation live、看板状态行「运行中/队列」计数正常、无加载失败。
- dsh-settings-nav-icons(导航图标):本包 client 半区声明 `{ 'dsh-cron-board': 'plan' }`;dsh-settings-nav-icons 已就绪时经 `__navicIcons` 直接注册,未就绪时本包入队 `__navicIconQueue`,由其启动时排空统一渲染。同装时验证设置导航出现「定时任务」图标,且两插件加载顺序颠倒时图标不丢。
- 共存底线:任意插件组合下页面不得出现 `Failed to load plugins`;其他插件 HMR 重建后本插件样式不得丢失(样式注入带 data-plugin 契约,client-id 测试锁定)。

## L3 功能面断言

断言于隔离宿主上以 playwright 执行;选择器与文案均对照 src/client.js 校准。

### 基础面

| # | 操作 | 预期 |
|---|------|------|
| 1 | 页面加载后 `document.body.innerText` | 不含 `Failed to load plugins` |
| 2 | 先锚定侧栏容器再匹配:定位含「新会话」按钮的侧栏容器(`「新会话」按钮.closest(...)` 沿祖先上溯到侧栏面板列表层,记为 `container`),在该容器内执行 `[...container.querySelectorAll('button')].find(b => (b.getAttribute('aria-label')||b.textContent||'').trim() === '定时任务')`(精确等于;设置卡片头 aria-label 为「展开: 定时任务」且 textContent 带描述,天然不匹配) | 找到入口按钮(侧栏「新会话」下方面板行);点击后 2s |
| 3 | 面板文本 | 含「全部」(类型过滤组)与「新建任务」按钮(任务列表渲染);列表为空时另有「还没有定时任务」空态文案 |
| 4 | 点击文本为「新建任务」的按钮,2s 后页面文本 | 含「保存」与「取消」(编辑器打开),另有调度频率分段「每天/每周/工作日/固定间隔/自定义」 |

| # | 操作 | 预期 |
|---|------|------|
| 5 | **默认态(开关关)**:侧栏「新会话」下方 | 有「定时任务」面板行;点击 → 中央区切到看板,**会话保持不动**(layout.selectPanel 官方路径) |
| 6 | 默认态:点击会话行或「新会话」 | 中央区切回会话(官方路径切回),无看板残留 |

## 专项注意

- 启动隔离宿主必须带 `DSH_CRON_BOARD_DATA_DIR=<临时目录>`:没有它,测试建的任务会被生产实例的调度器拾取执行(测试不是只读操作)
- 新建编辑器只打开不保存,测试不留脏数据;任务卡「运行」按钮会真实 spawn 进程或向会话投递任务,测试勿点
- `sidebarTab` 开关状态持久(settings cron-board 命名空间),测试完把开关拨回默认「关」
- `sidebarTab` 开关需 better-sidebar 已装载;隔离 profile 已含 `dsh-better-sidebar@0.19.0`(以实际 profile 装载为准);但测试 bundles 若为纯单包,better-sidebar 不在——开关应呈**禁用态仅展示**,保持全局面板,无副作用。这一态也是断言 #14
- 本包 node_modules 不含 dsh-better-sidebar(仅 croner):侧边栏开关可用性是宿主服务软探测结果,与包依赖无关,勿据包目录内容预判开关状态
- 误判防范:
  - 形态切换由客户端 5 秒轮询(status.ui.sidebarTab)驱动,断言前等满一个轮询周期;面板行/页签未变化多为未到轮询点,不是切换失败
  - 「定时任务」文案分布:侧栏面板行常驻;设置导航图标与设置>插件页卡片仅在设置视图渲染进 DOM,并非三处同时出现。入口类断言(#2)必须先锚定侧栏容器再匹配,禁止全页 querySelectorAll('button') 扫描;卡片类断言用 `.cb-pc__name` 锚定,防止命中错目标造成假阳性
  - 任务卡每 30 秒自动刷新,「下次 x 后」相对时间自然走动、「运行中/队列」计数变化属正常,勿判为调度异常
  - 环境变量列表值恒为打码形态(长度不超过四字符全打码,其余保留前 2 后 2),是接口行为不是数据丢失;编辑回填走明文单条接口
  - 失败重跑前更换或清空临时数据目录:任务/运行记录/日志均持久,历史数据会破坏「还没有定时任务」空态等断言
- 断言保留记录:原 10 项断言(基础 4 + 联动 6)全部保留,无一删除,仅收紧预期措辞与选择器;原判据「侧边栏联动 6 项」随补充更新为 10 项

## 判据

activation live + diagnostics findings 0 + 页面无 `Failed to load plugins` + 基础面 4 项与侧边栏联动 10 项全部通过。

- activation live:宿主设置>插件 页本插件卡片呈已激活(运行)状态,启动日志无本插件装载报错
- diagnostics findings 0:宿主诊断(diagnostics)面板中与本插件相关的 findings 计数为 0,无兼容性告警
