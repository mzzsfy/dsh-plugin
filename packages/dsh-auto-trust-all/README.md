# @mzzsfy/dsh-auto-trust-all

DeepSeek Harness web 入口插件:动态信任所有实际到达的 Host——`dsh web` 启动后,任何实际到达的入口(泛域名、内网 IP、反代域名)等效已被 `--trusted-host=<实际到达的 host>` 静态放行。不干预监听绑定:web 监听地址由部署层决定(`--host` 旗标或宿主缺省 `127.0.0.1`)。

## 功能

- **动态信任**:包装 webServer 函数型路由处理器(exact / prefix / upgrade,以及 fallback 的 handler 形态;0.2.2 起 fallback 亦可为 `{ resource }` 资源对象,资源由宿主 `readResource`/HTTP 分发直接消费,非函数不参与包装,本条信任登记对其无意义),含激活前已注册与后续新注册,请求到达即提取 Host 头(与官方信任闸门同构的 WHATWG 解析:小写、去端口、IPv6 保留方括号),去重后写入 `connection` 服务实例的 `trustedHosts` 数组——各代宿主(0.2.0 线 / 0.2.1 线 / 0.2.2 线)的 `/api` 信任闸门都实时读它,无需重启;`webRuntime.trustedHosts` 在场时同步镜像(0.2.0 线同构自守卫插件读它,0.2.1 及以后线宿主已移除该服务,缺席即静默降级)。泛域名(`*.example.com`)等无法枚举的入口不再需要改启动命令。
- **LRU 容量**:注册域名容量 `maxHosts` 默认 100(上界 4096),超出按最久未访问淘汰,活跃入口不易被挤出;淘汰同步作用于两类数组,内存总量恒定有界。官方初始条目(部署派生的局域网 IP 等)与 loopback(`localhost` / `[::1]` / `127.x`——官方闸门对其恒放行,登记零增益;`*.localhost` 官方不放行,照常登记)不参与记账。淘汰只撤本插件实际推入的条目,他方写入的同名条目不越权删除;数组换代(宿主重建信任数组)时动态条目按 LRU 记账回填新数组。
- **换代撤销**:跨代归属表(域名 -> 拥有该条目的代号令牌)**按宿主实例(webServer)分区**——同一实例内的换代(行级 config 变更、市场启停、同包双行重叠)共用一张表,双实例/多工位并存时各自一张,任一代只撤销自己实例的条目;新代接管时把前代仍持有的条目从两类数组移除并输出 `auto-trust-all: revoked host <域名>`,本代从零记账——旧动态信任不留存至重启,`maxHosts` 始终约束实际在位条目。撤销只作用于本插件实际登记过的条目(按数组台账或跨代归属与记账识别;宿主重建数组后无需新请求触发重记亦可撤销),他方写入的同名条目不越权删除。
- **console 输出**:启动时输出一行状态横幅(绑定、容量、既有信任条目、镜像形态);此后每次注册输出 `auto-trust-all: registered host <域名>`、每次淘汰输出 `auto-trust-all: evicted host <域名>`、每次换代撤销前代条目输出 `auto-trust-all: revoked host <域名>`,直接 grep dsh console 即可做入口审计。
- **绑定不干预**:bundle patch 只插入本插件行,不覆盖官方 webserver 行(0.2.1 及以后线宿主拒通配绑定且 bind 策略属宿主所有)。需要非回环监听时由部署层显式配置,配方按代际不同:0.2.1 及以后线 `--host <具体内网 IP>`(CLI 直收);0.2.0 线 CLI 拒绝 `--host 0.0.0.0`、schema 只收 `127.0.0.1`/`0.0.0.0`,唯一途径是 profile patch 覆盖 webserver 行 `host: '0.0.0.0'`(即旧版本本插件 patch 的做法)。缺省 `dsh web` 监听 `127.0.0.1`,同机 nginx 反代到回环即可。
- **认证层不动**:只影响官方 Host/Origin 信任闸门(官方文档明言"绝不建立身份"的可达性闸门);原生浏览器 cookie 认证与 dsh-web-startup-auth 会话闸门原样保留,安全增量趋近于零。
- **干净降级**:冷启动时 `connection` 尚未就绪属预期,插件挂服务激活事件自动延迟启用;等待提示延后——超过 15 秒仍未就绪才输出 `connection 未就绪` 等待行,正常启动不产生该行;`connection.trustedHosts` 冻结等形态异常时告警后停用;官方 web 面形态变化(路由表缺 Map 形态或注册方法缺失)时告警后停用——均不产生启动 pending、不影响 dsh 启动与其余功能;`webRuntime` 缺席(0.2.1 及以后线)只影响镜像,不影响注册主路径。
- **卸载即撤销**:每代在 webServer 的代际注册表(`Map<token, {fiber, registerHost}>`)占一项,包装器每请求解析最新 ACTIVE 代;卸载只删自己项——仍有 ACTIVE 代时注册自动交回最新代(新旧代重叠且新代先卸载时旧代继续服务,不会因单槽载体被清空而永久静默失效),全部代卸载后注册链才停止。条目按跨代归属表从两类数组移除仍属本代的全部条目——已被新代接管的域名归属已转移,不误删;信任放行随插件移除停止。

## 配置(无 GUI)

唯一配置项 `maxHosts`(注册域名容量,自然数,默认 100)。走 cordis 行级配置,在 profile 的 `cordis.patch.yml`(或 `~/.dsh/cordis.patch.yml`)追加覆盖行,行级配置变更经热重载换代即按新容量生效,无需重启:

```yaml
- id: auto-trust-all
  config:
    maxHosts: 200
```

容量按激活代记账:换代(行级配置变更、市场启停、同包双行重叠)时前代条目一律撤销——先卸载的路径由 disposer 移除,新旧代重叠的路径由新代接管时按跨代归属表移除;本代从零记账,旧动态信任不留存至重启,`maxHosts` 统计的就是实际在位条目。前代随后卸载时归属已不符,不误删新代条目;无新代接管的真卸载同样把本代条目从两类数组移除。

## 安装

任何 `dsh plugin add`(开发或发布安装)都会把 node_modules 里的既有 junction 重建为实体目录,装完必须重跑 `node scripts/dev-link.mjs all` 恢复工作副本挂载,否则改仓库源码不生效。

发布版安装:

```sh
dsh plugin --profile web add @mzzsfy/dsh-auto-trust-all
```

开发安装(仓库工作副本直挂,不经 npm 发布):

```sh
node scripts/dev-link.mjs dsh-auto-trust-all   # 仓库根执行:归一 profile 依赖行 + 挂 junction
```

bundle patch 经 dev-link 维护的 hmr 覆盖行保存约 5 秒防抖窗口热重载;规约与全仓归一见 `node scripts/dev-link.mjs all`。

## 与其他插件的关系

- **dsh-web-startup-auth**:完全共存。本插件不提供任何 cordis 服务,零服务冲突;两者都会遮蔽 webServer 注册方法包装路由,委托链在任意激活顺序下保持正确(会话检查与 Host 注册同时生效)。未认证请求至多完成 Host 登记(纯观察),首个拦截点始终是会话闸门。配合语义:startup-auth 的账号会话(`dsh_sid`,30 天)+ 官方 cookie 铸币跳(会话通过但缺官方 cookie 的 GET 由它代签并 303 回跳)替代了 `?token=` 的 per-process 分发——重启 dsh 后浏览器免输 token;本插件则让泛域名新入口免改启动命令即可达。
- **dream-skin 等同构自守卫插件**:同样实时读 `webRuntime.trustedHosts`(仅 0.2.0 线宿主提供该服务),本插件的注册对它们同步生效;0.2.1 及以后线宿主已移除 `webRuntime`,该类插件需各自适配。

## 安全边界

放行的是可达性闸门:攻击者可让任意域名指向本服务并到达登录页(受 startup-auth IP 限速约束),拿不到任何数据。闸门内建的 `sec-fetch-site: cross-site` 拒绝与 Origin 同源检查独立于信任清单,不受本插件影响。泛解析范围控制与防火墙仍是运维责任。

原生 cookie 会话按 `主机:端口` 绑定,每个新入口(各子域、各内网 IP 形态)都需要各自登录一次——这是 dsh 原生行为,与本插件无关。

被 LRU 淘汰的域名在再次访问时自动重新登记:已包装路由的请求先于宿主闸门执行注册,淘汰条目重访即恢复(无需重启);LRU(最久未访问先淘汰)语义使活跃入口被低频新入口挤出的概率远低于按注册先后淘汰。

**全仓库约定(见 AGENTS.md 与 DEVELOPMENT/dsh-api-alignment.md「安全边界」节)**:本插件放行可达性闸门是项目级决策,所有插件包一律不自建认证层——不实现 Host 白名单、DNS-rebinding 防线、自有 token/cookie 校验。插件路由注册在 `/api/<pkg>`(exact 或更长 prefix),会先于宿主的 `/api` 前缀闸门命中,所以每个路由处理器首行回问 `connection.requestRejection`(复用宿主 Host/Origin 闸门与 cookie 认证,无 cookie 401),服务缺失时放行。写路由的跨源防护仍以 Origin 与 Host 同源比对为上限;审查报告把"缺自有 Host 校验"列为缺陷的条目一律无效。

## 已知行为与边界

- 卸载后,遮蔽的注册方法与路由包装标记滞留:其后新注册的路由仍会过一层透传包装(每请求一次注册表查找,代价微小),属防卸载期路由半包装的既定取舍,进程存续期不可逆。
- 激活后对 `webServer.fallback` 实例字段的直接赋值不经包装,该 handler 的请求不注册 Host(本插件只拦注册方法与激活时点已存在的路由);fallback 为 `{ resource }` 资源对象时同样不包装(非函数,资源由宿主读取)。
- 未认证请求至多完成 Host 登记(纯观察),首个拦截点始终是会话闸门;多样化 Host 流量下 registered / evicted / revoked 日志逐条输出,可作入口审计也可能成为日志噪声来源。
- 第三方直接收缩信任数组(原引用被 splice 清空)时,已记账条目的重访重新登记并补记台账,两侧(connection 与 webRuntime 镜像)同步回填,无需等 LRU 淘汰或重启;访问顺序按重访续期。被 LRU 淘汰的条目重访即自愈;换代由新代接管即撤销前代条目(含宿主重建数组直接携带旧条目的形态),不存在"留存至重启"的遗留。
- 换代撤销依赖按宿主实例分区的跨代归属表与按数组引用记录的写入台账:**台账只记本插件实际 push 进该数组的条目**——数组里既已存在的官方/他方/前代条目(含宿主重建数组时恢复的同名条目)一律不进台账,清理只按归属与代内记账兜底。删除前先校验归属与代内记账,归属已清或他方写入的同名/异名条目不越权删除,台账命中但归属不符时只清台账不动数组。**官方条目例外**:激活时两类数组里非动态的现存条目被记作官方类,宿主把它移出后即便由本插件动态补位,宿主重建数组恢复同名时卸载与换代都不撤销它(官方清单由宿主维护,不是本插件的动态残留)。
- 信任数组是名称级(宿主闸门按字符串比较),同名条目的写入方不可区分:本代仍持有归属时,他方从数组移除我们的条目后又写回同名,卸载/换代按名称撤销(与撤销自身条目同一路径);归属已随换代清理之后的他方写回不受影响。需要长期独立于本插件放行的同名入口,应由部署层静态信任或独立插件承担。开发期 HMR 文件重载会让 Node 重新求值模块(新实例的归属表为空),该路径由宿主先卸载旧代(disposer 按表清理)再装载新代,生产运行不重新求值模块,故不留残留。

## dsh 版本兼容

同一版本覆盖 0.2.0 线、0.2.1 线及 0.2.2 线宿主(共同契约:`connection.trustedHosts` 实时数组 + webServer 路由包装,均为各代源码核实的形态;`webRuntime` 镜像仅 0.2.0 线可用);0.2.1-rc.5 与 0.2.2-rc.1 线经隔离实测(横幅/注册/401/403/淘汰自愈/激活 live),0.2.0 线沿用既有登记。manifest `dsh.hostMin = 0.2.0-rc.2` 为本包验证过的最低宿主代际(dev-link / compat 装载层按其过滤);各线实测状态与登记见 manifest `dsh.compatibility.dshReleases`。**注意**:自本版本起 bundle patch 不再翻转 web 默认绑定——依赖旧版"零参数监听 0.0.0.0"的部署需按上文「绑定不干预」在部署层显式配置监听。逐轮实测结论见 `docs/兼容性测试/逐包测试进度.md`(本地维护,不入库)与本包 `兼容性测试.md`。
