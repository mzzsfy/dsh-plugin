# dsh-auto-trust-all 兼容性测试

包定位:包装 webServer 全部路由,把每个实际到达请求的 Host 头实时注册进 `connection.trustedHosts`(两代宿主 `/api` 信任闸门共同读取的数组;0.2.0 线 `webRuntime.trustedHosts` 在场时同步镜像),防伪造 Host 与泛域名入口被信任闸门拒绝;不干预监听绑定(部署层责任);认证层(原生 cookie 与 startup-auth 会话)原样保留。无 UI,断言全走 HTTP。

## L3 功能面断言

约定:探针端口按隔离环境实际端口(自动化 9291 段/人工 9191 段);`<T>` = boot 启动 token,取法:在 boot 日志中 grep `token=`,取 `token=` 之后的值(官方日志会把 URL 的 `http://` 截成 `ttp://`,只影响按整行复制 URL,grep `token=` 不受影响);伪造 Host 探针必须用 curl.exe(`-H "Host: ..."`),Node fetch 与浏览器把 Host 列为 forbidden header 不可显式设置,用它们会产生假阴性。探针域名无需 DNS 解析,Host 头纯文本即可。

## L4 共存层(全家桶共启交叉)

- 全家桶(全部 @mzzsfy 包 + `dshmarket` / `@deepseek-ai/dsh-base` / `@deepseek-ai/dsh-web-app` 三基座)共启:本包 activation live、findings 0,#3 探针仍 200;console 无插件报错。
- 与 dsh-web-startup-auth 完全共存:两者都会遮蔽 webServer 注册方法,委托链任意激活顺序保持正确(L1 场景 6a/6b 锁定)。实测判定:未认证 index 请求先完成 Host 登记(registered 行出现,纯观察先行),随后被会话/认证层拒绝(401 认证文本或 303 回跳,非数据);认证后探针 200。本包不提供任何 cordis 服务,零服务冲突。
- 与 dream-skin 等同构自守卫插件:它们实时读 `webRuntime.trustedHosts`(仅 0.2.0 线宿主提供),本包镜像注册对其同步生效;该数组无独立 HTTP 观测面,镜像正确性由 L1 场景 14/22/41 覆盖;0.2.1 线宿主无 `webRuntime`,该类插件需各自适配(横幅显示「缺席」)。
- 日志噪声交叉注意:多样化 Host 流量下 registered/evicted 日志逐条输出,全家桶日志审计时属预期行为,勿误判为异常;可作为入口审计手段使用。

## 专项注意

- **本包无 UI,全部断言走 HTTP,不需要 playwright**;判定「信任生效」以 #4 的 registered 日志为硬判据(伪造探针的 HTTP 200 打在无 Host 检查的 market 读端点上,不构成信任证明);68 字节认证文本(401 `dsh web authentication required; ...`)是 index 认证失败形态,只应出现在打 `/` 的请求上。
- **探针工具**:Node fetch 与浏览器禁改 Host 头(forbidden header),必须用 curl.exe(`-H "Host: ..."`);浏览器探针自带 `sec-fetch-site` 头,受官方闸门 cross-site 拒绝影响,与 curl 探针形态不同,勿混用判定。curl 不发 `sec-fetch-site`,不受该拒绝影响。
- **拦截层全景(读磁盘官方源码静态定案,0.2.0-rc.2 与 0.2.1-alpha.2 双闭包核对;dshmarket 行为口径 = compat pin(scripts/compat/lib.mjs DSHMARKET_PIN),该版 market 读端点无 Host gate——pin 升级后 market 路由若改走宿主闸门,本表 200 判据须复核)**:webserver 纯路由分发,无任何检查。connection 服务的 Host/Origin 闸门只作用于其 channel 路由(`/api` 类 prefix,检查在 route.handler 内):Host 可信(本包注册先于闸门执行,首个请求即过)+ `sec-fetch-site` 非 cross-site + Origin 可选(存在时须 `new URL(origin).host` 与 Host 头 WHATWG 归一化 host **含端口**全等);**Referer 无任何层检查**;闸门失败 403 "forbidden",过闸未认证 401 "unauthorized"。index 页面(`/` 与 dist index)走 authorizeIndex:cookie(按 Host authority 绑定)或 `?token=`(GET `/` 铸币 303),失败 401 + 68 字节认证文本。其余插件自有路由按注册方自定:dshmarket 的 `/dsh-market/installed` 为 GET 读端点,无 sameOrigin、无 cookie 检查(变更类 POST 才查 `new URL(origin).host === Host` 原串),故本表伪造探针打它恒 200,装/未装本包无差;本包生效的判据是 registered/evicted 日志,fence 侧正确性由 L1 场景 22/38 覆盖。
- **token 与探针的关系**:token 机制仅服务 index 页面认证(`?token=` 只在 GET `/` 上生效,铸按 Host authority 绑定的 cookie 后 303 回 `/`),与 Origin/Referer 无关——不存在「带来源头即可免 token」的检查。本表全部探针(#3-#15)默认无需 token/cookie,唯一用 token 的是 #10 的页面 URL。若首轮实测 API 探针返回 401(端点认证行为随 market/宿主版本变化),按铸 cookie 序列校准:`curl.exe -s -c jar.txt "http://127.0.0.1:<port>/?token=<T>"` 后加 `-b jar.txt` 重试,并把实测结论回填对应断言项。
- **绑定面归部署层**:本包 patch 不覆盖 webserver 行,监听地址 = 宿主缺省(回环)或部署层配置;非回环配方两代不同——0.2.1 线 CLI 直收 `--host <具体内网 IP>`;0.2.0 线 CLI 拒 `--host 0.0.0.0` 且 schema 只收 `127.0.0.1`/`0.0.0.0`,唯一途径是 profile patch 覆盖 webserver 行 `host: '0.0.0.0'`。`Get-NetTCPConnection` 找不到监听时先确认旧进程已杀净——端口被占时新进程启动报错退出,探针若仍通是打到了未杀净的旧进程,会得出「改了没生效」的假结论。
- **淘汰语义**:淘汰域名重访即自愈——注册记账无黑名单,重访与首注册同一路径重新登记并恢复信任(#13),evicted 行是容量审计信号而非拉黑标记;默认容量 100,长时间多域名测试留意挤占。两层语义勿混淆:L1 mock 层与真实链路的重访自愈走同一注册路径(场景 16);外部直接收缩信任数组(原引用被 splice 清空)时,已记账条目重访不回填(命中记账即短路),恢复途径 = 淘汰后重访/换代回填/重启,属既定行为非缺陷。
- **冷启动语义**:延迟激活、等待行、横幅等启动时序判定必须冷启动验证,HMR 热重载掩盖竞态。
- **隔离环境**:按 `docs/兼容性测试/测试与隔离方法.md` 走 run.mjs/boot-keep.mjs 自动化(DSH_HOME 隔离 + 工位预置的插件数据目录隔离 env 见 scripts/compat/run.mjs,9291 段端口,冷启动清 sessions);被测宿主用 `pnpm add @deepseek-ai/dsh@<版本>` 装到独立目录(npm 在该依赖树上组合爆炸,必须 pnpm)。生产 `~/.dsh` 与 3080 端口零接触。

## 维度检查点(补充)

1. **两代信任面**:0.2.0 线横幅「镜像 webRuntime 在场」,0.2.1 线「缺席」;两代 `/api` 信任闸门均实时读同一数组。
2. **归一化边界**:`Probe.Evil.Test:8443` 与已登记 `probe.evil.test` 同形不重复登记;`[2001:db8::1]:3080` 登记为 `[2001:db8::1]`。
3. **绑定不干预**:patch 只插入本插件行,不含 webserver 覆盖与 `0.0.0.0` 字样。
4. **冻结与换代**:`trustedHosts` 冻结时告警停用而非抛错;数组换代后按 LRU 回填且归属延续。
5. **卸载撤销**:卸载后新域名不再出现 registered 行;恢复启用后重现;不误删他方写入条目。
6. **安全口径**:不得把「缺 Host 白名单/token 校验」判为缺陷;本包只做可达性放行,身份仍由宿主 cookie/startup-auth 承担。
