# dsh-rs-workflow 兼容性测试

包定位:释放「若水工作流」强规则编排(v5)。宿主侧单行 board(role=board,经 cordis.patch.yml 注入 profile 根)挂 `/api/rsww/*` 设置子域路由(模板 CRUD/校验/规范/配置读写/运行记录/控制/释放链);编排运行时不落宿主根——由释放链把流程模板生成为 `rs-<模板id>` Agent 预设组合(内含 orchestrator 行注册 `rs_workflow_*` 七工具与 template-tool 行注册 `rs_workflow_template`),在 Agent 预设页以「若水·<label>」卡片呈现,进入即得工作流会话。客户端半区自注册(`__ModuleLoader__.load`):设置页「若水工作流」分区(流程模板管理 + 工作位/预算配置)与会话页签「若水编排」(运行记录,条件注入)。数据与模板存自有文件 `<DSH_HOME>/dsh-rs-workflow/v5/`(templates.json / config.json / runs/),不经宿主 settings 服务,不写 settings.yaml;释放物落 `.agent-presets/rs-<id>/` 四文件,marker 归属标记。

| 层 | 内容 | 手段 |

### L2 装载层

- 冒烟覆盖:仓库根 `node scripts/smoke-load.mjs` 遍历 packages/ 全部含 package.json 的目录(junction/symlink 亦收),动态 import 各包 main(支持 `--profile` 测 profile 安装副本)。本包 main 为 lib/index.js,入口存在、必真实测(脚本内「实现暂缺的包跳过加载」注释为过期残留,不据此期待 SKIP);import 即拉起全量模块图(@deepseek-ai/schemastery peer 与 @deepseek-ai/dsh-tools 等 `@deepseek-ai/*` 依赖靠目录逐级兜底解析到 dsh 本体全局安装目录),宿主升级移除模块或命名导出时当场 FAIL。该脚本只 import 不 apply:行注册与服务注入面由隔离 boot 判据覆盖。
- 隔离环境 boot 判据(bundles = 基座 + 本包):boot 后 dsh-market 本包 activation live、diagnostics findings 0、boot 日志无本包 pending/报错;`GET /api/rsww/templates` 返回 200 且 `templates` 为数组(board 行已挂载的权威判据);页面无 `Failed to load plugins`。隔离实例必须独立 `DSH_HOME`(如 ~/.dsh-isolate);建议同时设本包自有覆盖 env——`DSH_RS_WORKFLOW_DATA_DIR`(数据)与 `DSH_RS_WORKFLOW_PRESET_ROOT`(释放物),两者优先于 DSH_HOME 生效,指向专用临时目录可与生产彻底隔离。下节文件断言路径按「DSH_HOME=~/.dsh-isolate 且未设本包 env」的缺省解析书写(释放 = ~/.dsh-isolate/.agent-presets/rs-<id>,数据 = ~/.dsh-isolate/dsh-rs-workflow/v5);设了本包 env 则按 env 路径替换。
- 干净禁用形态:client 半区 inject `['slots','sessions']`,宿主缺服务时 client fiber 不激活、不阻塞 web 启动;board 行 inject `['webServer']`,缺服务时行 pending 不崩宿主(webServer 缺失 apply 无异常由 index-roles.test 锁定);orchestrator 与 template-tool 行只存在于释放的 rs-<id> 组合(delegation 组 isolate.workflowEngine 预设私有),宿主根不注册编排行——宿主降级最多损失设置面,不产生加载崩溃。

## L4 共存层

- 全家桶共启交叉:`/api/rsww/*` 为 exact 前缀独占注册,与其他包路由无冲突;路由自带守卫(跨源 403、非 JSON content-type 400、写路由 POST-only、请求体 256KB 上限),不依赖宿主 CORS 面。settings.section id rs-workflow-board(order 45)与 conversation.view id rsww-flow(order 15)均含包名,与其他插件 slot 注册零冲突;会话页签为条件注入——仅当前会话存在 rs 运行记录才挂载(5 秒轮询),其他插件会话中不出现属预期。
- 导航图标:client 声明 `{ '若水工作流': 'flow', 'dsh-rs-workflow': 'flow' }`,经 `__navicIcons` 或 `__navicIconQueue` 入队,由 dsh-settings-nav-icons 统一渲染;该插件未就绪时入队等待,同装时验证设置导航「若水工作流」图标出现。
- 样式契约:style 注入带 data-plugin=@mzzsfy/dsh-rs-workflow,其他插件 HMR 重建后本包样式不得丢失(client-id/client-guard 测试锁定);共存底线:任意插件组合下页面无 `Failed to load plugins`。
- 预设目录归属防线:.agent-presets 为宿主与其他工具共享目录,本包以「rs- 前缀目录 + 本包 marker(package 且 kind=flow)」双条件认领;release 对外来目录拒覆盖、marker 缺失拒换入,unrelease 对外来目录返回 foreign 不删(release.test 锁定),与其他写入该目录的包互不误伤。
- 预设私有服务:rs-<id> 组合的 workflowEngine 为 delegation 组 isolate 预设私有服务(预设组合发布全局服务会被宿主拒绝 mount),全家桶下不产生全局服务名冲突;board 与 orchestrator 行经同一 realpath 解析共享 store/控制队列模块单例,属同包内聚,不外溢。

## 专项注意

- 释放触发点(v5):释放**不再发生在插件激活时**——激活只注册 board 行;释放由显式操作触发(设置页「保存并创建」/「创建到 dsh」,或会话内 rs_workflow_template 的 save release:true)。D 组文件断言失败先确认释放操作已执行,再查 boot 日志有无本包 pending/报错与 board 行 activation live。
- 危险操作标注:release/unrelease 直接改写 .agent-presets(宿主将其下目录装载为真实可选模式);「移除模式」「删除」「删除步骤」为两段 armed 确认按钮,断言点一次仅进入待确认态,须再点「确认…」;测试模板固定 id compat-test,测完必须走 #21 清理;隔离实例与生产实例共用 DSH_HOME 时释放物会被生产实例扫描装载——隔离 boot 必须独立 DSH_HOME(建议再加本包两覆盖 env)。
- 误判防范:
  - 「若水工作流」文本出现在设置页分区(分区名与标题);预设页卡片名是「若水·<label>」,预设页找不到「若水工作流」字样不是缺陷(#17 按前缀断言)。
  - 会话页签「若水编排」条件注入:当前会话无 rs 运行记录时不出现(5 秒轮询),属预期;断言页签须先有本会话 run。
  - 「保存并创建」/「创建到 dsh」失败常见因:模板已禁用、目标目录被外来目录占用(marker 不符)、跨流程 flow 引用集合校验失败;错误横幅全文可见,先读文案再归属。
  - 预算输入失焦自动钳制 [1,10]、工作位留空=缺省链,是前端归一行为,非保存失败。
  - 运行记录 LRU 保留 200 条:断言前清隔离数据目录(runs/),防历史 run 污染空态类断言。
