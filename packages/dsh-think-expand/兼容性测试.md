# dsh-think-expand 兼容性测试

包定位:纯前端插件,最后一条思考行自动展开(thinkBody 可见性控制)。Host 半区 src/index.js 为零依赖空壳(`export function apply() {}`,profile 行仅用于让 client 模块系统发现本包 dsh.client 声明并服务浏览器半区 src/client.js)。行为全集:流式思考行出现(data-state="running")自动展开最新一条;新思考行出现收起上一条由插件展开的行;用户手动展开/收起优先,识别后不再干预;打开会话/刷新/切换会话展开最后一条、其余保持收起;插件动作前置底时高度落定后回补置底;同一时刻至多一条思考行展开。宿主依赖全部为官方 DOM 字面量与 client 模块系统注册形态,无服务注入、无 peerDependencies、不注入样式、不写 DOM 属性;任一依赖点缺失表现为整体不干预(干净降级),不加载崩溃、不阻塞 boot。

### L2 装载层

- 冒烟覆盖:scripts/smoke-load.mjs 遍历 packages/ 下全部含 package.json 的目录(symlink/junction 一并收),逐个动态 import 各包 main——OK/FAIL 逐行输出,入口缺失打 SKIP,任一包加载失败即 exitCode 1;`--profile` 参数切换为遍历 profile node_modules/@mzzsfy 测安装副本。本包 main 为 src/index.js,在清单内:空壳零 import,冒烟仅验证入口模块可解析可加载;src/client.js 非 main 不被该脚本 import,其装载由本层 boot 判据与 L3 覆盖。本包无宿主服务依赖与 peerDependencies,不存在缺依赖 pending 面。
- 隔离环境 boot 判据:`dsh plugin add @mzzsfy/dsh-think-expand` 经 cordis.patch.yml 在 profile root 插入行(id=think-expand,name=@mzzsfy/dsh-think-expand),重启一次宿主完成首装载;判据 = activation live + diagnostics findings 0 + 无 pending/装载错误 + 页面无 `Failed to load plugins`。host 半区空壳不注册任何服务,任何宿主代际下不 pending、不拖死 boot;client 半区经 `__ModuleLoader__.load` 自注册,装载失败仅表现为功能不生效(世代槽缺失,L3 #2 直接暴露),不产生页面级报错。

## L3 功能面断言

断言于隔离宿主上以 playwright 执行;选择器与官方字面量均对照 src/client.js 校准。沿用既有等待约定:页面加载/会话打开/刷新等 9s、交互后等 2s、渲染断言前等 2.5s;流式组受模型响应延迟支配,不用固定等待,按 2s 间隔轮询、单步上限 30s。环境前提见专项注意首条。

宿主 DOM 依赖点(断言与排障共同参照;全部为官方字面量,缺失后果即本包的干净降级形态):

| 依赖点 | 形态 | 缺失后果 |
|---|---|---|
| `[data-conversation-scroll]` | 官方滚动容器字面量属性 | 容器缺失插件待命,无任何动作 |
| `[data-variant="think"]` | 官方思考行根节点字面量属性 | 行集为空,不干预 |
| `[data-disclosure-row]` | 官方折叠头字面量属性 | 行 headable=false,该行永不干预 |
| `data-state` ∈ running/ok | 官方行状态字面量 | 非两值即识别失败,整体降级不干预 |
| `aria-expanded` | 官方展开态字段,点击动作的唯一判定依据 | 展开判定失效,动作不触发 |
| `[class*="thinkBody"]` | 正文类名 CSS Modules 哈希带前缀,子串匹配 | bodyText 空:仍展开但不登记,接管收起退化 |
| `__ModuleLoader__.load` | 宿主 client 模块系统注册形态(id=完整包名) | client 半区不装载,世代槽缺失 |

本包不注入任何样式、不写任何 DOM 属性,唯一 DOM 写操作是对折叠头调用 `click()`。

| 12 | 未被手动操作干扰的流式期间任意时刻求值 `document.querySelectorAll('[data-variant="think"] [data-disclosure-row][aria-expanded="true"]').length` | ≤ 1(至多一条展开契约全程保持) |
| 13 | 流式结束(该行 `data-state` 变 'ok')后等 2.5s | 该行保持 `aria-expanded === 'true'`(流式结束保留展开) |

## L4 共存层

- dsh-settings-nav-icons(导航图标):client.js 顶层声明 `{ 'dsh-think-expand': 'spark' }`,经 `window.__navicIcons.register` 直注,或 `__navicIconQueue` 入队(本插件早于其就绪时入队,由其启动时排空);键为市场短名,即发现页收录显示形态。同装验证设置内本包条目带 spark 图标;该插件缺失时仅图标不渲染,入队路径不报错,不判失败。
- 与官方折叠组件共存:本包仅模拟点击官方折叠头(按 aria-expanded 判定,与官方组件状态机一致),不直改 DOM 内部状态、不写属性、不注入样式,与其他插件无样式与属性冲突面。全家桶下验证官方折叠行为正常、至多一条展开契约保持。
- 观察器共存:body 哨兵 + 会话容器子树观察常驻(只读),与同样观察 DOM 的插件互不接管;本包自身 client 重评估经 window 世代槽(Symbol.for('@mzzsfy/dsh-think-expand'))先拆上一代观察器与挂起计时,不产生双决策机并发点击。其他插件 HMR 重建与本包无交叉:无样式可被误删,观察器身份独立。
- 共存底线:任意插件组合下页面无 `Failed to load plugins`;全家桶共启后本包 activation live、diagnostics findings 0、打开会话自动展开行为与单包一致(#1–#7 抽查)。

## 专项注意

- 环境前提:隔离 profile 预置会话样本必须含思考内容(thinkBody 才存在)。样本 A(单轮单思考行,如「回复一个字:壹」)必配,#4–#6 依赖其单行形态;样本 B(同一会话多轮多思考行)用于 #7–#10 的「仅最后一条」断言。流式组(#11–#18)要求宿主配置可用模型 API,且发送回合处于产生思考的形态(会话思考开关开启/模型支持思考,与样本 A 的产生条件一致),API 不可用或回合不产思考时整组记「环境不可测」并在报告注明,不判失败但不得冒充通过。
- 样本初始状态:打开样本前各思考行须处于官方默认收起态(planFinal 才有展开动作可观察);上一轮测试遗留的展开态刷新页面即重置(刷新后官方默认全收起,插件重展开最后一条)。
- 误判防范:
  - offsetHeight 语义:`offsetHeight > 0` 即展开、折叠态为 0,不受 CSS 可见性类属性干扰;该判据前提是官方以高度/显隐方式折叠,若官方改用 visibility/opacity 类折叠则判据失效——先核官方 DOM 实测再判本包
  - thinkBody 选择器命中全部行:`[class*="thinkBody"]` 按文档序返回所有思考体,展开的通常是最后一条;断言展开体必须锚定行内查询(row.querySelector),勿以 b[0] 代表展开体(样本 A 单行除外,#6 已注明语境)
  - 类名漂移:#6/#7 length=0 时先核官方类名是否改名(thinkBody 为 CSS Modules 哈希前缀子串匹配),再查本包 pending;类名漂移时插件仍展开(bodyText 空仅展开不登记),表现为接管收起退化而非展开失效
  - 状态字面量扩张:识别仅认 data-state running/ok,宿主引入新字面量时行识别失败、插件整体不干预(干净降级),表现为「不自动展开」——先核官方行状态字面量再判本包回归
  - 手动操作污染标记:手动展开/收起会写入 manual/read 标记(页面生命周期内有效),断言失败重试前先刷新页面重置 registry,勿带脏标记重试
  - 流式时序:新思考行出现与展开动作间隔为 50ms 防抖,2s 轮询不会错过展开态;模型延迟波动大,单步上限 30s 未出现按超时计,先查宿主日志确认请求是否发出;流式中手动展开较旧行属时序敏感场景,L3 不设断言(手动意图的确定性形态见 #15 与 #16)
- 危险操作:本包无数据目录、无持久化、无宿主服务写入,模拟点击折叠头无破坏性,测试不留脏数据。唯一成本:流式组断言真实消耗模型 API 配额,重试勿频繁发送长消息。
- 断言保留记录:原 2 项全部保留融入,无一删除——原 1 → 新 1(措辞原样保留);原 2 → 新 6(限定样本 A 单思考行语境,b[0] 即展开体,预期不变)。多行场景的展开可见性改由 #7 以行内锚定方式覆盖。
