# dsh-llm-pi-gateway 对表指南

本包是官方 `@deepseek-ai/dsh-llm-pi-ai` 的镜像增强包(减目录分支)。官方演进后若不对表,
就会出现「宿主已升级、镜像语义停在旧版」的功能缺失——典型事故:模型发现缺
anthropic-messages 协议分支(修复见 git log `99f7782`),及其后 audit 出的 9 项漂移。
本文是对表的操作规程与机械防线,宿主升级、官方发版、pi-ai 升级时按此执行。

## 对表锚(单一事实源)

当前锚:**官方 dsh-llm-pi-ai 0.1.5-rc.2 / pi-ai ^0.85.1**。

锚的三处落点必须一致,升级时同一提交内同步改:

1. `package.json` devDependencies(`@deepseek-ai/dsh-llm`、`@deepseek-ai/dsh-llm-pi-ai` 精确版本)
2. `README.md`(开头对表锚声明 + 「官方兼容」节)
3. `兼容性测试.md`(定位句)

## 官方源码在哪

| 途径 | 路径 | 用途 |
| --- | --- | --- |
| 宿主安装树(最权威) | `<nvm node_modules>/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-llm-pi-ai/lib/index.js` | 日常比读 |
| pi-ai 同树 | `<nvm node_modules>/@deepseek-ai/dsh/node_modules/@earendil-works/pi-ai/dist/`(`types.d.ts` + `api/*.js`) | compat 类型与协议行为 |
| 仓库快照 | `.dsh-versions/<版本>/node_modules/.pnpm/@deepseek-ai+<包名>@<版本>_<hash>/node_modules/...` | 跨版本 diff、宿主不在本机时 |

`lib/index.js` 是打包产物,官方源码的 `#region` 注释就是函数级索引,按函数名搜索即可定位。

## 什么时候必须对表

1. 宿主(dsh 本体)升级后——官方包随宿主走
2. 官方独立发版、或官方 `package.json` 里 pi-ai 依赖范围变化时
3. 出现疑似功能缺失(某能力在官方可用、本包不可用)——**先对表再修,禁止凭感觉补**
4. 本包升级 pi-ai 依赖时(三同步,见下文)

| 面 | 官方锚(在 lib/index.js 内按名搜索) | 本包文件 |

方法:官方 lib/index.js 搜函数名 → 比读本包对应实现 → 每处差异归类:
**漂移**(官方演进而本包没跟上)→ 补实现对表;**有意偏离**(见下文豁免表)→ 确认注释在锚。

## 机械防线(test/pi-ai-parity.test.mjs)

人眼比读会漏,三条机械断言在每次依赖安装后的测试里自动生效:

| 断言 | 抓什么 | 红了怎么办 |
| --- | --- | --- |
| 三协议 compat 名单与装机 pi-ai `types.d.ts` 双向一致 | 官方加字段(名单漏)或删字段(死名单) | 比读官方源码,决定纳入名单或登记偏离,勿直接改测试 |
| 枚举类值域(`COMPAT_VALUE_CHECKS`)与 types.d.ts union 一致 | pi-ai 给枚举字段加值/改值 | 同步值域表;pi-ai 对未知拼写静默按缺省处理,不同步 = 用户配置看似生效实则无效 |
| 协议全集与官方 `supportedProtocols()` 双向一致 | 官方加协议(本包无路由/发现分支,即 99f7782 事故类)或删协议(死路由) | 补 `PROTOCOL_MODULES` + discovery 分支,或清理名单 |

注意:守卫锚的是**装机版本**的 pi-ai(读 `node_modules/@earendil-works/pi-ai/dist/types.d.ts`)
与 devDependencies 锚的官方包——所以 `pnpm install` 之后必须跑测试才算对表;
类型守卫只覆盖 compat 与协议面,上下文转换/replay/接管校验等行为面仍需人工比读六类面。

## pi-ai 升级三同步

compat 名单(`src/config.mjs`)+ 值域表(`COMPAT_VALUE_CHECKS`)+ 依赖下界(`package.json`)
必须同一提交内同步:

- 只升依赖不改名单 = pi-ai 新字段静默漏网(用户配了被守卫拒绝,或行为缺失)
- 只改名单不升依赖 = 名单引用不存在的字段 = 静默 no-op

升级后必查的行为性变化(会随 pi-ai 自动生效,需在 README/兼容性文档声明),
以 0.84.4 → 0.85.1 为例:responses 默认开始发 `max_output_tokens`;anthropic beta
头改为请求体 `betas` 数组;静态 beta 头从「与自动 betas 合并」变为「完全替换」。

## 有意偏离豁免表

这些差异是设计决策,不是漂移;对表遇到直接跳过,但每条必须有注释/文档锚。
**新增偏离必须先登记本表再写代码**:

| 偏离 | 理由 | 锚 |
| --- | --- | --- |
| 减目录分支(无 catalog 物化) | 包定位:手写路由 + 接管官方节 | README「官方兼容」 |
| 官方 withhold 的 compat 字段全开放(含 supportsMidConvoEffort/allowedFallbackModels) | 包定位「compat 全开放」,官方 withhold 是其目录面产品选择 | `src/config.mjs` 名单头注 |
| usage 产出带 null 守卫;`mapStopReason` 有 default 兜底 | 插件强于官方,非漂移 | `src/pi-stream.mjs` |
| 不引入流空闲 watchdog | 监督在 runtime 层,引入即新特性 | README「已知取舍」 |
| 目录 error 条目 `declared` 恒 true | 条目必指向真实存储声明(官方 catalog 条目为 false) | `src/manager.mjs` `directoryEntries` 注释 |
| 注册期不强制 deferred 全量校验 | 启动 `profiles()` fail-loud 与官方注册期 deferred 拦截面等价 | `src/index.js` `validateSection` 注释 |
| gateway 节 modelOverrides 硬拒 / 官方节 skip+诊断 | 手写配置 fail loud;官方 schema 合法产物不硬拒整节 | `src/config.mjs` `officialRouteServable` 注释 |

## 发现功能缺失后的处置流程

1. 定位官方对应实现(lib/index.js 搜能力关键词;不在六类面清单内的,按官方 `#region` 索引找)
2. 判定类别:官方已有而本包缺失 = 漂移 → 补实现对表;官方新能力 → 按豁免表评估后决定纳入或偏离
3. 补对表测试:优先消费真实官方包(参考 `test/takeover.test.mjs` 的 `import('@deepseek-ai/dsh-llm-pi-ai')` 形态),机械可比对的进 `test/pi-ai-parity.test.mjs`
4. 更新对表锚三处与本文档;一组提交一事一议
