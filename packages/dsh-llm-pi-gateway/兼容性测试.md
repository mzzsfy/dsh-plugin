# dsh-llm-pi-gateway 兼容性测试

包定位:官方 `dsh-llm-pi-ai` 的零感知增强替换(装上即接管、卸载即还原),以官方包自己的 Config schema 接管 `llm-pi-ai:` 设置节,路由名与既有配置原样保留,向每个上游请求注入 sessionId 供网关粘性路由;`llm-pi-gateway:` 节用于独立或增强路由。镜像语义包:配置 schema、请求装配、错误分类、生态声明口与官方逐项对表(当前对表锚:官方 0.1.5-rc.2 / pi-ai ^0.85.1),官方公共导出能复用的一律复用。

## 测试分层与执行流程

| 层 | 内容 | 手段 |
|----|------|------|
| L1 单元层 | 17 个测试文件的逻辑 BDD + 宿主升级后官方新源码逐项对表 | 包目录 `node --test "test/*.test.mjs"`;对表方法见下 |
| L2 装载层 | 全包加载冒烟 + 隔离环境 boot 接管/让位状态 | 仓库根 `node scripts/smoke-load.mjs`;boot 日志判据见下 |
| L3 功能面层 | 基础面 + header 注入三通道 + 禁用三路径(playwright 实证) | 下节断言全集 |
| L4 共存层 | 下游客包 dsh-model-capability-editor 依赖 + 全家桶交叉 | mce 测试 bundles 并入本包;全家桶冒烟 |

执行顺序:L1 → L2 → L3 → L4,前层失败即止,修复后从失败层重跑。

### L2 装载层

仓库根 `node scripts/smoke-load.mjs`(默认测仓库工作副本,`--profile` 测 profile 安装副本):全包逐个动态 import 各包 main,命名导出缺失或模块错误当场暴露。本包 main 为 src/index.js,在遍历清单内——宿主升级移除 `@deepseek-ai/dsh-llm` 等宿主包命名导出时此处立即 FAIL。src/guard.js 与 src/client.js 非 main,不被该脚本 import:guard 逻辑由 L1 的 guard.test.mjs 覆盖,client 半区装载由本层 boot 判据覆盖。

隔离环境 boot 判据(bundles = 基座 + 本包):boot 后 dsh-market 本包 activation live、diagnostics findings 0,boot 日志无状态异常文案。接管 / 让位状态按日志归类(引文为子串匹配,非整行):

| 日志文案 | 状态 | 处置 |
|----------|------|------|
| 「官方 llm-pi-ai 行未被禁用(用户层启用),本包降级为只服务 llm-pi-gateway 节」 | 让位态 | bundles 组合错误或官方行 patch 未生效,先查 cordis.patch.yml 是否生效 |

## L3 功能面断言

### echo 接收器(header 实证前置,方法内联)

隔离 profile 无 NEWAPI_API_KEY,真实 newapi 不可用,header 实证用本地 echo 接收器替代:

1. 起服务:临时 HTTP 服务监听 `127.0.0.1` 未占用端口,收到任何请求先记录 method/path/headers/body(头名统一小写键),再以 200 回显 JSON 包裹的原文,并保留最近一次请求供断言;最简 node http 脚本数十行即可,无外部依赖。
2. 准备凭据:先经凭据服务(Web Models 页)或启动环境存入 `ECHO_KEY`(任意非空值)——凭据服务在场即唯一来源,缺失时请求在凭据解析即抛 `MISSING_CREDENTIAL`,echo 端收不到任何请求。
3. 注册路由:写入 `settings.yaml` 官方节并同时实证零感知接管——`llm-pi-ai.providers.echo-anthropic: {api: anthropic-messages, baseURL: 'http://127.0.0.1:<端口>', apiKeyEnv: ECHO_KEY, models: [{id: auto, contextWindow: 200000}]}`;openai 通道另加 `llm-pi-ai.providers.echo-openai`(api 用 openai-responses)。
4. 发话与断言:页面选中 echo 路由模型发一轮对话,在 echo 端留档处按下表断言;每个用例先改 `settings.yaml` 再发话(配置热更新即时生效,无需重启)。

### header 注入实证(三通道,echo 端断言)

| # | 通道 | 操作 | 预期 |
|---|------|------|------|
| 3 | 请求体标记(anthropic) | 经 echo-anthropic 默认配置发一轮对话,读 body | `body.metadata.user_id` 匹配 `^dsh:[0-9a-f]{40}$`:onPayload 直写的派生标记(`dsh:` 前缀 + sha256 前 40 位),默认开启,不是裸 sessionId |
| 4 | 请求体标记(openai 系) | 经 echo-openai 发一轮对话,读 body | `body.prompt_cache_key` = 同格式派生标记;模板 metadata 不上 wire(openai 系声明 metadata 无效果),无 `prompt_cache_retention` 副作用 |
| 5 | 亲和头 | echo-anthropic 加 `compat: {sendSessionAffinityHeaders: true}` 发一轮;echo-openai 原样再发一轮 | anthropic 头 `x-session-affinity` = 裸 sessionId 原样(与标记通道值形态不同);openai-responses 无需 compat 即默认发射 format `openai` 头集合(`session_id` + `x-client-request-id`) |
| 6 | 亲和头门控 | echo-anthropic 与 echo-openai 两条路由都改 `cacheRetention: none`,各发一轮 | 两条路由的全部亲和头均消失;body 标记仍在(请求体通道不受 retention 影响) |
| 7 | 静态 headers | echo 路由声明 `headers: {x-gateway-group: pool-a}` 再发一轮 | `x-gateway-group: pool-a` 原样到达;`user-agent` 保持官方 `deepseek-harness/` 前缀——attribution 保留头不被静态头覆盖,撞名头大小写不敏感剥除 |

单测 `test/dispatch.test.mjs` 锁装配;本节是真实宿主链路(pi-ai → fetch → echo)实证,尤其第 5、7 行的亲和头发射与保留头语义由 pi-ai / 请求头装配在真实链路完成。

基线还原(用例 3-7 全过后必做):移除两条 echo 路由的 `cacheRetention: none`(还原亲和头发射),其余 compat / 静态头保留并留档该配置——此状态即「禁用前基线」,禁用三路径的「三通道注入与禁用前一致」以此为准;不还原则亲和头恒被 none 抑制,用例 9/10 的恢复断言必然失败。

## L4 共存层

- 下游客包 dsh-model-capability-editor(唯一有数据面依赖的包):其兼容测试 bundles 必须并入本包(基座 + 本包 + mce),注入锚点以本包接管的 `llm-pi-ai` 节路由为前提。本包升级、接管行为或官方节语义变化后,必须连带执行 mce 包 `兼容性测试.md` 全部断言。
- 全家桶交叉:全部插件包同装 bundles 冒烟——boot 无 `Failed to load plugins`,本包排他注册面(adapter / directory / discovery / settings 命名空间)不与其他包冲突;仓库根 `node scripts/smoke-load.mjs` 全包遍历同此用途。

## 专项注意

- 测试 bundles = 基座 + 本包,无数据依赖,可纯单包。
- 隔离 profile 无 NEWAPI_API_KEY(真实 newapi 不可用),header 实证一律走上节 echo 接收器。
- 误判防范:
  1. 标记通道值是派生标记 `dsh:<40 位 hex>`,不是裸 sessionId;裸 sessionId 只出现在亲和头。echo 端标记按格式正则断言、亲和头按原值断言,两者不可互换。
  2. 亲和头缺失按序排查:compat 门控(anthropic-messages / openai-completions 需 `sendSessionAffinityHeaders: true`,openai-responses 默认发射)→ `cacheRetention: none` 抑制 → format 头集合差异(openai / openai-nosession / openrouter 头名不同,不能拿单头名一刀切)。
  3. 禁用窗口内 echo 请求无注入头是官方插件语义(代挂或原生接管),不是回归;先确认当前处于哪条禁用路径再判。
  4. market 开关每次会对哨兵行记「行 id 含特殊字符,不支持写入补丁层」警告,属预期噪音,不作失败。
  5. bundles 漏装本包时官方插件原生服务,同样模型可用且无注入头——与「接管失效」表象相同;先核对 bundles 组成与官方行 disabled 状态再定归属。
  6. 宿主能力探测读运行宿主注入的服务对象,不以仓库工作副本解析链命中的宿主包副本为准(rc.2 教训);宿主兼容结论以隔离 profile 实测为准。
  7. 补丁层恢复接管后,官方退场受在途流拖长时存在短暂降级窗口(仅本包节服务,官方节路由可能暂时无人服务);退场超时警告出现后补接管完成无日志,以间隔重发对话、echo 端断言恢复为准,不立即判失败。
  8. HTTP 头名大小写不敏感:echo 端断言头前先小写规范化;静态头 `User-Agent` 等变体被剥除属正确行为。
