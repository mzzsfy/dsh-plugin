# dsh-llm-pi-gateway 兼容性测试

## 定位

gateway 装饰官方 `llm-pi-ai`，官方插件保持 provider 注册、设置节与模型发现。gateway 不注册 adapter、directory 或 discovery。它用官方 namespace 的 directory entry.provider 查询 adapter registration，核对 registration.provider.id，仅对提供 `streamWithSnapshot` 的官方 adapter 实例授权。Models facade 每次调用绑定来源实例，不同实例即使共享原型或 Models 也不串 owner。

directory route 移除不会立即撤销已授权实例的 owner，授权持续至 gateway dispose；reapply 时清理失活 owner。协议行为为 Chat 补 `session_id`、`x-client-request-id` 请求头，Anthropic 注入派生 `metadata.user_id`，Responses 与未知协议原样透传。

## 验证层次

| 层 | 仓库根目录命令或方法 | 断言与范围 |
| --- | --- | --- |
| 单元(对应协议 L1) | `npm test --prefix packages/dsh-llm-pi-gateway` | marker 派生、Chat 头、显式值与 null 优先、不可变、none/开关/卸载、模型告警、Responses 透传、owner 授权与共享实例隔离 |
| 仓库加载(对应协议 L1 冒烟) | `node scripts/smoke-load.mjs` | 仓库插件入口可导入，不验证运行时装配 |
| 三协议实际 adapter(对应协议 L3 功能面) | 下方 affinity-probe 命令 | 真实官方 PiAiAdapter → Models → gateway → pi-ai → 新起的 echo-upstream；检查成功流终态和实际 HTTP 字段；provider 为手工 fixture，不验证 Cordis 与 GUI |
| 隔离 GUI(对应协议 L2+L3) | 独立 DSH_HOME/profile、echo 随机端口；按下方步骤用有头浏览器操作 | 官方 provider 注册、gateway live/findings 0、当前对话回复渲染、实际会话 ID 与上游字段对应 |

```sh
node scripts/compat/affinity-probe-3proto.mjs --host-dir .compat/0.2.1-rc.2/dsh-host   # 示例为本机历史工位,按实际隔离闭包目录替换
```

前置为对应目录已安装 DSH 及其 pi-ai 依赖。探针仅使用该宿主代码，不启动 DSH 服务；每轮启动独立 echo-upstream 随机端口实例，保留临时目录中的 `llm-echo.jsonl` 和成功结果 `result.json`，在 finally 结束模拟器。任何异常 finish、缺失正文、路径/请求数/字段断言失败均以非零退出，不记为成功。

### 三协议断言

- 每种协议发送同一 sessionId 两轮，再以新 sessionId 发一轮；同会话键一致，新会话键不同，流成功终止且正文含 fixture 标记。
- Chat 两个头均等于原始 sessionId；不新增 metadata、prompt_cache_key、prompt_cache_retention 或 x-session-affinity。
- Responses 在已验证的 pi-ai `1.3.0` 默认保留两个会话头与请求体顶层 prompt_cache_key。gateway 不修改 Responses options，行为由宿主依赖决定。
- Anthropic metadata.user_id 匹配 `dsh:<40 位小写十六进制>`。
- 关闭 gateway 开关后，Chat/Anthropic 不再自动注入，Responses 原生键仍在；Chat/Responses 的 cacheRetention none 抑制各自自动键。
- Chat 大小写混合的显式头优先，owner dispose 后不再补头。模型头与 null 抑制等其他边界由单测覆盖。

### 隔离 GUI 方法

按仓库 `docs/兼容性测试/测试与隔离方法.md` 与 `scripts/compat/run.mjs` 同款数据隔离方法准备独立 profile。仅加载 gateway bundle，官方 llm-pi-ai seed 声明 echo-openai、echo-anthropic 路由，provider baseURL 均指向本次新起的模拟器；设置独立 `DSH_HOME`(工位统一预置的插件数据目录隔离 env 见 scripts/compat/run.mjs)，选择空端口，禁止修改生产 profile 或重启生产宿主。浏览器使用有头模式。

准备 profile 可复用 `scripts/compat/profile.mjs` 的 `buildProfile`，传入 `version`、独立 `workRoot`、已安装的 `hostDir`、`only: ['dsh-llm-pi-gateway']`、`seedGateway: true`、`gatewayBaseURL: 'http://127.0.0.1:<本次模拟器端口>'`；再按 `scripts/compat/run.mjs` 的 boot 方法启动宿主。从输出的认证 URL 进入页面。当前宿主的页面会话 ID 可在 DevTools 同源页面上下文读取 `JSON.parse(localStorage.getItem('dsh.sessions.current')).sessionId`，在每轮发话后采样。

1. 核查 `/dsh-market/installed` API 中 gateway activation 为 live、diagnostics.findings 为空，模型列表可选 Echo Model 与 Echo A Model，页面没有插件加载失败横幅。
2. 选择 Chat 模型发送两轮，在同一页面采样当前 sessionId；检查本轮 user 节点、fixture 回复、composer 清空及 UI error/alert 为空。上游主请求的两个头必须均等于此 ID。
3. 新建会话并发一轮，采样新 sessionId；上游头必须换成新 ID。同一会话的标题生成等附属请求也应使用对应会话键。
4. 切换 Anthropic 模型发一轮，检查当前回复渲染，并以 marker 派生函数核对上游 metadata.user_id。
5. 保存请求 JSONL、关键页面截图和结果；结束本轮启动的宿主、模拟器与浏览器窗口，复核 PID 与端口退出。

GUI roundtrip 不作为协议流完整终态的证据：DOM 没有稳定跨协议终态信号，显示完整 delta 后异常中断仍可能通过 UI 文本检查；成功终态由实际 adapter 探针单独断言。Compat runner 专用的 `--echo-user-message` 仅影响 default Chat/Anthropic 回复，Responses、think/tool 与公共 CLI 默认保持固定内容。consoleErrors/httpFailures 在现有 runner 中仅供诊断。

### owner 生命周期

`test/decorator.test.mjs` 覆盖同实例 owner 切换、重复 sweep 幂等、同原型未授权实例隔离、跨原型共享 Models、route 移除后的持续授权、旧 owner dispose 与重新 apply。单测不模拟 Cordis fiber 或事件 listener 装配。本轮隔离 GUI 证明冷启动装载路径与请求链路，未单独验证真实 fiber 的 dispose/reapply 或 listener 后续重扫时序。

(随包 0.8.1 发布)

## 维度检查点(补充)

1. **官方形态漂移**:升级宿主后先核对 `llm.adapters` 是否为 Map、adapter 是否带 `streamWithSnapshot`;不符时只告警禁用,不得替换或代注册 adapter。
2. **注册时序**:官方 adapter 晚于 `apply` 注册时,`llm/adapters-updated` 必须补扫;`apply` 时 0 adapter 只告警,不 pending、不崩。
3. **三协议字段**:Chat 两个会话头等于原始 sessionId;Anthropic `metadata.user_id` 匹配 `dsh:<40hex>`;Responses 与未知协议原样透传,不新增 chat 头或 metadata。
4. **开关与抑制**:关闭 `sessionMarker` 后 Chat/Anthropic 不自动注入,Responses 原生键仍在;`cacheRetention: none` 抑制各自自动键。
5. **owner 生命周期**:route 移除后已授权实例持续到 dispose;reapply 清理失活 owner;同原型未授权实例隔离,跨原型共享 Models 不串。
6. **错误透传**:上游 401/429/5xx、流中断、finish 异常不被改写或吞掉;探针以非零退出记录失败,不得记为成功。
7. **凭据边界**:请求头里 Authorization/API Key 与官方直连一致;日志与留档不打印 Key。
