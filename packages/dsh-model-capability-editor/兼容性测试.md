# dsh-model-capability-editor 兼容性测试

包定位:官方「模型」页 provider 编辑卡内,展开「自定义设置」并点开模型行尾高级箭头后,模型行官方展开区(上下文窗口/最大输出所在条件渲染块)内注入「模型能力」行内编辑块(思考档位七档开关 + 线上拼写 + 输入模态四态,单模型「应用」即经 settings RPC 写回);收起箭头,编辑块随官方展开区一同卸载消失。官方 DOM 结构变化导致行内锚点失效时,模型页右侧浮动「模型能力」入口回退(点开为完整编辑卡)。纯 client 包:host 半区为空实现(src/index.js 仅导出 name 与空 apply,职责是让 bundle patch 行可解析),全部行为在 src/client.js。**唯一有数据面依赖的包**:读写经 settings RPC 的 `llm-pi-ai` 命名空间(describe/mutate 整组写回 providers.<route>.models),该节由 dsh-llm-pi-gateway 接管提供,测试 bundles 必须并入 gateway。

## 测试分层与执行流程

| 层 | 内容 | 手段 |
|----|------|------|
| L1 单元层 | 12 个测试文件:逻辑 BDD + 双副本同源守卫 + 源码结构静态守卫 | 包目录 `node --test "test/*.test.mjs"` |
| L2 装载层 | 全包加载冒烟 + 隔离环境 boot 装载判据(按宿主代际) | 仓库根 `node scripts/smoke-load.mjs`;boot 判据见下 |

### L2 装载层

仓库根 `node scripts/smoke-load.mjs`(默认测仓库工作副本,`--profile` 测 profile 安装副本):逐包动态 import 各包 main。本包 main 为 src/index.js(host 半区空实现),命名导出缺失或模块错误即 FAIL;src/client.js 非 main 不被脚本 import——client 半区装载语义由 L1 client-boot.test.mjs(宿主种子桩装载)与 client-scope.test.mjs(vm 整源求值)覆盖,真机装载由本层 boot 判据覆盖。

隔离环境 boot 判据(bundles = 基座 + gateway + 本包):boot 后页面加载 9s 无 `Failed to load plugins`(否定存在性,观察窗语义见 L3 断言 1),market 双 live + findings 0——映射 L3 断言 1 与 3;断言 2 的装载形态探测归 L3 执行,L2 不重复。

装载断言按宿主代际选形态,断错形态会误判 404:

- 0.1.1-rc.2:聚合 URL `plugins/??<逗号清单>`,fetch 后 `decodeURIComponent` 再查包名;HTML/script src 可能查不到。
- 0.1.2-rc.1 起:独立 URL `plugins/@mzzsfy/dsh-model-capability-editor/client.js` 返回 200;且带 token 的页面 HTML 内含 ≥1 处 `model-capability-editor` 引用。
- **遇新宿主先探测形态**:先试独立 URL,404 再试聚合 URL,以实测为准记录回本文档本节。

client 注入契约代际(装载即定型,由 L1 client-boot.test.mjs 锁定):0.1.2+ 的 boot wire 带 `batches` 批次调度(宿主 parseBootManifest 校验其为必填数组),点分声明 `['remote', 'remote.settings']` 交由 cordis 门控,fiber 等 namespace `$mount` 完成才激活,激活即就绪;0.1.1 的 wire 无该 namespace,点分声明会永远 pending 拖垮整页 boot,故声明两代基座 `['remote', 'connection']`,settings 传输在 apply 内异步定面轮询(50ms 节拍,满 1s 窗口恒定禁用并告警恰一次,不阻塞 web 启动)。两代均禁止 apply 内同步探测 typed settings 面——同步探测跑在挂载完成前会误报缺失而自禁(mce 0.2.1 在 0.1.2-rc.1 实测事故)。

## L3 功能面断言

前提(bundles 与数据面,内联):bundles = 基座 + `@mzzsfy/dsh-llm-pi-gateway` + `@mzzsfy/dsh-model-capability-editor`;隔离 profile 的 llm-pi-ai 配置含第三方 provider(如 newapi,anthropic-messages 协议,models 列表非空)——没有 provider 卡则注入无对象,先补配置再测(隔离环境搭建:以 `DSH_HOME=%USERPROFILE%\.dsh-isolate` 为隔离 home,复制生产 profile 的 package.json / cordis.yml / .npmrc / pnpm-workspace.yaml 后 `pnpm install --prefer-offline`,被测包以 junction 指向仓库工作副本,启动时带该 `DSH_HOME` 与独立 `--port`)。

### DOM 定位锚点(判定用的查询链,全部断言共用)

按 src/client.js 的判定路径自上而下,执行者先取锚点再跑断言,禁止臆造选择器:

| 锚点 | 查询 | 说明 |
|------|------|------|
| 设置分区 outlet | `document.querySelector('[data-slot="settings.section"]')` | 模型页的宿主挂载点;`outlet.querySelector('h2').textContent` 须精确等于「模型」(en「Models」),用于确认当前在模型页而非其他分区 |
| 模型 ID 输入 | `outlet.querySelectorAll('input[aria-label^="模型 ID"], input[aria-label^="Model ID"]')` | 每模型行一个,zh/en 宿主双前缀都查;第 N 个输入对应第 N 行 |
| 行头(modelRow) | `idInput.closest('div')` | 行头 = 模型 ID 输入、显示名称输入、高级箭头、删除按钮的共同父 div |
| 行条目(entry) | `modelRow.parentElement` | 行条目常驻可见,面板严禁挂在这里(历史上挂错 here 导致未点箭头即显示的缺陷) |
| 高级箭头 | `modelRow.querySelector('button[aria-expanded]')` | 行头内唯一带 `aria-expanded` 的按钮,**结构定位,不依赖翻译文本**(zh 宿主 aria-label 前缀为「容量」、en 为「Capacities」,仅作人工核对辅助,禁止写进断言);展开态 `aria-expanded="true"`,收起态 `"false"` |
| 官方展开块(advanced) | `[...entry.children].find((child) => child !== modelRow)` | 官方条件渲染:箭头点开才存在于 DOM,收起即被移除;内部含「上下文窗口」「最大输出 token」两个官方字段(zh,en 为「Context window」/「Max output tokens」。注意 zh 第二字段是「最大输出 token」——ModelListEditor 用 `t("modelMaxTokens")`;「最大输出 token 数」是 deepseek 家族卡的 `t("maxTokens")`,不在被测对象上) |
| 插件面板 | `advanced.querySelector(':scope > .mce-inline-root')` | 面板容器的唯一合法位置 = 展开块的直接子元素;内层编辑块 `.mce-inline` |
| 插件样式 | `document.getElementById('mce-style')` | 全局唯一,位于 `document.head` |

异步时序约定(全部断言适用):注入 = MutationObserver 150ms debounce + settings describe RPC + React 提交;卸载 = 官方移除展开块 + 150ms debounce + reconcile 孤儿清理。两条链都在 1s 内完成,但**禁止 sleep 固定值后单次断言**,统一用轮询:playwright 写 `page.waitForFunction(轮询体, undefined, { timeout: 5000 })`(三参形态,第二参为传入轮询体的 arg;二参写 options 是 Puppeteer 签名,在 Playwright 下会静默落到默认 30s 超时)。两条附加规则:

- **轮询体必须自包含**:waitForFunction 的函数体序列化后在页面上下文执行,Node 侧取好的锚点变量进不去;且 React 随时可能重建节点,持旧引用会误判。每拍在轮询体内按「DOM 定位锚点」表重新求值。示例(断言 7 的轮询体):

  ```js
  () => {
    const outlet = document.querySelector('[data-slot="settings.section"]')
    if (outlet === null) return false
    const idInput = outlet.querySelector('input[aria-label^="模型 ID"], input[aria-label^="Model ID"]')
    if (idInput === null) return false
    const modelRow = idInput.closest('div')
    const advanced = modelRow === null ? undefined : [...modelRow.parentElement.children].find((child) => child !== modelRow)
    const root = advanced?.querySelector(':scope > .mce-inline-root') ?? null
    return root !== null && root.querySelector('.mce-inline') !== null && root.offsetHeight > 0
  }
  ```

- **否定存在性检查(断言 1)语义相反**:「某文本不得出现」要在整个观察窗内持续轮询、窗口结束仍未出现才判 PASS;写成出现式 waitForFunction 会在 t≈0 立即通过,观察窗失效。手工验证纪律分两种:出现式断言在控制台手动重跑判定表达式直到成立或超时,超时即 FAIL,不得放宽为「可能还没刷出来」;断言 1 相反——9s 窗口结束仍未出现即 PASS,窗口内任意时刻出现即 FAIL。
