# dsh-settings-nav-icons 兼容性测试

包定位:设置弹窗导航图标自定义(内容改写制:决策写进官方 svg 的 innerHTML,`data-navic` 记账)+ dsh-market 插件市场卡片头像槽图标。纯前端包:src/index.js 为空 apply,无宿主半区逻辑,cordis.patch.yml 插入的 profile 行(id `settings-nav-icons`)唯一职责是让 client 模块系统发现 `dsh.client` 声明并材质化 web 半区(src/client.js)。功能面两域:设置弹窗导航(齿轮换专属图、右键覆盖浮层、导航滚动补偿)与市场卡片头像槽;对外提供 `window.__navicIcons.register` / `window.__navicIconQueue` 声明机制,是全仓 12 个生产者包的公共依赖面。

## 测试分层与执行流程

| 层 | 内容 | 手段 |
|---|------|------|
| L1 单元层 | test/ 下 3 个 `*.test.mjs`:client 注册 id 守卫、双实现同源 parity(场景双份 + 全表 deepEqual + 逐函数源码对比)、编排层契约(清单见下) | 包目录 `node --test "test/*.test.mjs"` |
| L2 装载层 | 全包冒烟加载 + 隔离宿主 boot 判据 | 仓库根 `node scripts/smoke-load.mjs` + 隔离 profile 启动 |
| L3 功能面层 | 基础接管面 7 项 + 样式滚动面 3 项 + 声明消费面 4 项,另选测 5 项(即下节断言全集) | playwright 页面断言(隔离宿主),断言全在宿主原生 DOM(设置弹窗 / 市场卡片),本包无独立设置分区 |
| L4 共存层 | cron-board 图标声明消费(`__navicIcons`/`__navicIconQueue`)、全仓 12 生产者样板、全家桶交叉 | 同装验证 + 页面级回归 |

执行顺序 L1 → L2 → L3 → L4,前层失败即止,修复后从失败层重跑。

### L2 装载层

- 冒烟覆盖:scripts/smoke-load.mjs 遍历 packages/ 全部含 package.json 的包并 dynamic import 其 main。本包 main 为 src/index.js(空 apply,无宿主半区依赖,无 inject),在清单内,FAIL 仅在模块语法/导出损坏时发生;src/client.js 非 main,不被该脚本 import,其装载由本层 boot 判据覆盖。支持 `--profile` 测 profile 安装副本。
- 隔离环境 boot 判据:bundle 经 `dsh plugin add @mzzsfy/dsh-settings-nav-icons` 注入后重启宿主完成首装载;判据 = activation live + diagnostics findings 0 + 页面无 `Failed to load plugins`。本包无宿主服务依赖与门控,不存在缺依赖 pending;唯一失效形态是 client 半区材质化失败,表现为页面 `Failed to load plugins` 横幅。插件正确生效的进一步判定进入 L3。
- 干净禁用形态:本包 client 消费端无版本脆弱宿主 namespace 依赖(纯 DOM 观察,不 inject 任何宿主服务),任何宿主版本下要么生效要么因 DOM 锚点漂移静默不接管(见专项注意第 1 条的漂移判定),不存在加载崩溃路径。

### L4 共存层

- cron-board 图标声明消费(真实跨包交互面):dsh-cron-board client 半区注册 `{ 'dsh-cron-board': 'plan' }`,样板为「__navicIcons 在场即 register,否则数组态入队 __navicIconQueue,队列也不在则自建」,由本包 orchestration 生产者样板契约测试锁定。本包启动时排空队列、启动后以直通桩承接 push、卸载恢复数组形态。键 `dsh-cron-board` 为市场短名,命中 dsh-market 卡片头像槽取图(plan 时钟);cron-board 若在设置导航出现「定时任务」分区,该分区取图按取图链推导(该中文 label 无内置映射与声明键,落关键词/哈希兜底),图形随链不预设。同装判定:window.__navicIconDeclarations 含 `dsh-cron-board` 键且值为 plan 的归一化 svg;市场卡片 dsh-cron-board 行头像槽带记账与注入图标;无 `Failed to load plugins`。
- 全仓生产者面:12 个生产者包(含本包自画像 `{ 'dsh-settings-nav-icons': 'tune' }`,client.js 模块级先于 load 注册)全部经同一机制声明;全家桶同装时设置导航各插件分区均应有图标(齿轮全被接管),`__navicIcons` 单一命名空间无冲突。
- 样式共存:本包 2 条 style 均自带 `data-plugin="@mzzsfy/dsh-settings-nav-icons"`,宿主 claimStyles 只收无标记节点,其他插件 HMR rebuilt 的整批删除不会命中本包样式;全家桶交叉后重复断言 L3 #8。
- 卸载恢复:market 移除或禁用本包后刷新页面,官方默认图标全部恢复(无宿主半区状态、无持久化副作用;localStorage `__navicUserIcons` 为独立键,残留不影响官方 UI,重装即恢复覆盖)。
- 共存底线:任意插件组合下页面不得出现 `Failed to load plugins`。

## 专项注意

- 宿主混淆类名漂移判定与应对:`.VOzbGW_navLabel` / `button.VOzbGW_navCell` / `.VOzbGW_navList` 是宿主 CSS Modules 混淆类名,`VOzbGW` 哈希前缀**换宿主版本可能变**。判定顺序:#4 通过而 #2/#10 失败 → 类名前缀漂移,不是包逻辑失效——在设置页 DOM 确认导航真实类名,记录漂移结果并评估 client.js 内字面量(`SELECTOR_LABEL`/`SELECTOR_CELL`/`NAVLIST_SCROLL_CSS`,client 与 logic 双侧同源)是否需同步更新;#4 同失 → 官方设置弹窗结构改版,升级本包锚点前包保持静默不接管(无崩溃)。市场卡片侧锚点(`[class$="_av"]` 等后缀匹配)抗哈希漂移,nav 侧精确字面量是已知漂移风险点。
- data-navic 计数语义(对照源码校对):#3 计数 = 「当前为官方齿轮且已被本包改写的分区数」,只由官方 DOM 里齿轮分区的数量决定。映射表/用户覆盖是否命中**不改变**计数——齿轮分区即使无任何映射(走关键词/哈希兜底)同样被改写并记账;齿轮被换掉后的已记账 svg 不再是齿轮,也不会重复计数。计数为 0 的合法情形仅一种:宿主 DOM 无齿轮分区(官方全部原生图标)。原文档「映射被用户清空时为 0 属正常」与 0.4.x 内容改写制源码不符(清空后回兜底管线仍接管),已修正。
- 计数与标签数随 bundles 变化:#2 = 5、#3 = 2 针对基座单包 + 隔离 profile 无用户覆盖形态;全家桶同装时插件分区进入导航,#2 增大、#3 相应增大(新增齿轮分区全部被接管),勿拿 5/2 硬套,按「基座值 + 新增分区数」重算后断言。
- 本包无独立设置分区,无独立设置页:设置项即右键浮层,断言全在宿主原生设置弹窗与市场卡片 DOM 上。
- 误判防范:
  - #12/#13 会改写页面声明状态:声明持久层 `window.__navicIconDeclarations` 页面级、刷新即释放,用例间以刷新隔离;#17 的 localStorage 覆盖跨刷新存活,用完必须清除,否则污染后续轮次与 #3 基数
  - 齿轮路径前缀 `M14.0861` 是官方齿轮图形版本指纹,官方更换默认图标即失效,#6 失败先确认官方图标是否换版再判包回归
  - bell 特征 `M8 2.2` 依赖内置 GLYPHS.bell 当前 path,该表由 parity 测试锁定 logic/client 双侧同源,断言与实现同源漂移在 L1 被拦截,L3 不会单边失真
  - console 中 `[nav-icons]` 前缀警告是单项异常隔离的告警留痕(去重后单节点仅一条),偶发不判失败;持续多条才是 DOM 形态漂移的回归信号
  - 官方双语分区(通用设置/General)取图按等价组解析:覆盖/声明写在任一语言键,两种语言下都命中;语言切换后记账值变化(#19)是重取图结果,不是状态丢失
- 断言保留记录:原 3 项断言全部保留融入(#1/#2/#3,仅 #3 措辞由 `[data-navic]` 收紧为 `svg[data-navic]` 以匹配内容改写制记账语义,判定等价);原专项注意 3 条保留,其中「映射被用户清空时计数为 0」一条按源码校对后修正(见上),另两条原文保留并扩充。
