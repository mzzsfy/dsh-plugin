# dsh-tunnel 兼容性测试

包定位:宿主进程内反向代理。path 模式 `/p/<name>/` 前缀 strip 转发(保留 Host,附 `x-forwarded-host/for/proto`,3xx 同源根绝对路径 `Location` 单头补前缀,WS 任意路径);subdomain 模式摘取 `webServer.server` 的 request/upgrade 监听,Host 首标签命中即全路径全协议透传,未命中原样委托。向 ai 注册 `tunnel_open/list/ports/close/logs` 五工具(可开关注销);GUI 为设置 > 穿透隧道分区 + 窗口底部 `shell.bottom` 状态条(无隧道不占高度),均经公共 WS 总线 `@mzzsfy/dsh-tunnel` 刷新;请求日志为内存环形缓冲(默认 500 条,`requestLogLimit` 可调 0..2000,0 关闭,不落盘);持久化 `~/.dsh/dsh-tunnel/tunnels.json`(随 `DSH_HOME`,含 `enabled`),重启恢复。

分层定义见 [DEVELOPMENT/dsh-api-alignment.md](../../DEVELOPMENT/dsh-api-alignment.md) 条款 3;维度定义与判定口径见[兼容性检查总纲](../../docs/兼容性测试/兼容性检查总纲.md)。

## 维度检查点(在既有功能格之外)

### 双入口与转发正确性(D03/D05/D12)

1. path 模式:目标应用收到 `x-forwarded-host/for/proto`,Host 仍为入口 Host;3xx 的 `Location` 只对同源根绝对路径补 `/p/<name>` 前缀,绝对外域 URL 不改写;已带前缀的判定按 URL pathname 的路径段做,`?query`/`#hash` 原样保留且不被二次拼接。
2. subdomain 模式:隧道域名下 `/api/*` 与宿主 upgrade 路由**不**命中;未命中的 Host 原样委托宿主监听,宿主 GUI 不受影响。
3. path 模式不做全协议透传:仅 HTTP 前缀 strip + WS strip;需要根路径的应用必须走 subdomain。
4. 名称规则:纯数字拒绝(与纯 IP 首段冲突);子域名名等于**本次管理请求所在 Host** 首标签(如经 `dsh.example.com` 打开设置页却要建 `dsh`)→ 400 且不落盘,同一名字改用其它地址创建即放行;client 侧同判据禁用「创建」;路径入口不受此限。判据只取请求 Host,不读 `connection.trustedHosts`——该集合由 auto-trust-all 按到达 Host 动态累积,泛解析部署下用它判入口会把每个试用过的子域当入口(实测:换名仍被误拒)。分流侧不做任何信任面复核:子域隧道被访问时该 Host 正被登记进 trustedHosts,复核即自毁。

### 故障边界(D09/D11)

5. 目标端口无人监听 → 502,错误信息可读。
6. 目标接受连接但不回头 → `connectTimeoutMs` 后 504;头到即解除,SSE 长响应不被超时杀掉。
7. 目标在 WS 升级后断开 → 隧道侧清理,不残留 upgrade 监听/句柄。
8. `tunnels.json` 损坏或半写 → 启动不崩,按空表处理并告警;合法 JSON 内非法行逐行跳过并告警;不承诺按行恢复/坏行保留,下次 persist 覆盖为空表。

### 恢复与生命周期(D06/D08)

9. 重启前保持一条 path 与一条 subdomain 未 close → 重启后均恢复;设置分区与 `tunnel_list` 一致。
10. 恢复失败(目标已下线/路由占位冲突)→ 行保留磁盘、列表 `active:false` 且带 `error`;占位释放后下次激活重试成功。子域名行不因 trustedHosts 含同名首标签而挂起。
11. 卸载插件 → 监听层不摘,载体置空后宿主路由原样透传;`tunnel_close` 停对应载体;重启后无残留隧道。旧代 dispose 只回收本代 upgrade socket,不得误杀新代连接。

### 安全与配置(D10/D12)

12. 跨源 POST `/api/tunnel/tunnels` → 403;无 Origin 放行;非 JSON content-type → 400;管理面写路由统一走 `withRouteGate`,`DELETE` 无 JSON content-type 同样 400。
13. 伪造 Host 直连隔离端口 → 照常受理(仓库安全边界);不得把缺 Host 校验判为缺陷。
14. `aiTools` 关闭 → 新会话工具列表无五件;重开恢复;设置分区增删不受影响。
15. `connectTimeoutMs` 改动即时生效(无需重启),对已建立连接不追溯。
16. `requestLogLimit` 改动即时生效:调小后缓冲按新容量裁剪,`0` 时停止记录且代理行为不变;日志不落盘,插件停用或宿主重启后为空。

### 底部状态条(D03/D06/D14)

17. 无隧道、加载中或旧宿主无 `shell.bottom` 槽时不渲染、不占高度;有启用隧道时固定单行,单条给名称与开放时长、多条只报数量(超 24 小时追加警示文案);点击整行打开内嵌管理弹窗,弹窗不提供一键关闭;超过 24 小时标警示色;总线推送与页面恢复可见各刷新一次,空闲期无网络请求(本地 60s 时钟只重算时长)。

## 人工执行方式

执行前置(强制):按 [docs/兼容性测试/测试与隔离方法.md](../../docs/兼容性测试/测试与隔离方法.md) 的隔离红线执行,禁止在宿主机生产实例上直接测试——宿主经 compat 自动化装入隔离 pnpm 闭包,独立 `DSH_HOME`(工位统一预置的插件数据目录隔离 env 见 scripts/compat/run.mjs),compat 工位隔离端口(9291 段,多会话并发时在 9291-9310 段手动指定互不相同的 `--port`,勿都落默认);生产 profile、`~/.dsh` 与 3080 零接触。下述步骤中的宿主与端口均指隔离实例。

1. 隔离宿主启动(`node scripts/compat/run.mjs --version <v> --only dsh-tunnel --keep --port <段内自选端口> [--work-root <独立目录,同版本并发必加>]`,或 boot-keep.mjs 驻留形态 `--port <段内自选端口>`),token 取隔离工位 boot.log,不装生产 profile、不起生产 3080
2. 路径模式: ai 调 `tunnel_open`(name/app, targetPort/本地 http 服务端口), 浏览器访问 `http://127.0.0.1:<隔离端口>/p/app/`, 断言目标应用页面透出
3. 子域名模式: ai 调 `tunnel_open`(name/web, targetPort, entry/subdomain), 浏览器访问 `http://web.localhost:<隔离端口>/`, 断言根部署应用页面透出且 WebSocket 应用(如 jupyter)内核通道可用
4. ai 调 `tunnel_list`/`tunnel_close`, 断言列表含 entry/access 与关闭后回落宿主页面
5. 重启隔离宿主, 断言两类隧道均自动恢复(重启前未 close 的条目)
6. 自动化: `npm test` 全绿(行为语义;本包需要 `--experimental-test-module-mocks`,裸 `node --test` 会假红) + `node scripts/compat/tunnel-fullchain.mjs` 全链路 PASS(隔离实例九项探针)
7. ai 开关: 设置 > 插件 > 本包关闭「允许 ai 使用」→ 新会话工具列表无 tunnel_open/list/ports/close/logs; 再开 → 工具恢复可用; 期间设置分区增删照常; 断言设置页自动配置节出现 aiTools/connectTimeoutMs/requestLogLimit, 改动即时生效
8. 设置分区: 设置 > 穿透隧道可见(导航图标 globe, order 47);已开放列表、本机服务折叠/展开、手动添加、复制/打开、编辑(可改名)、停用/启用、删除二次确认;窄窗口下⋯菜单挂在 body、不被滚动区裁剪且可点;窄屏 375px 无横向滚动
9. 底部状态条: 无隧道时窗口底部不出现该行;建一条隧道后出现「隧道开放中 · 名称 · 已开放 X」,多条显示「隧道 N 条运行中」,超 24 小时未关追加警示文案;点击整行打开内嵌管理弹窗,弹窗内创建/编辑/停用/删除与设置分区一致,不提供一键关闭;Esc 或遮罩关闭弹窗,弹窗内再开编辑弹窗时 Esc 只关最上层;停用与恢复失败(`active:false`)条目不计;刷新页面与总线推送后条数同步;窄屏 375px 摘要以省略号收缩且无横向滚动
10. 请求日志: 设置分区「请求日志」默认折叠且不自动请求;展开后经隧道发一次 HTTP(200/404)与一次 WS 握手 → 卡片出现对应条目(时间/隧道/方法/路径/状态/耗时),WS 显示 `WS` 与 101,目标拒连显示 502 + 错误、超时显示 504;过滤框按隧道/路径/状态过滤;刷新按钮重新拉取;卡片内「保留」改为 2 并保存 → 设置落盘、旧条目裁剪、上限显示 2;改为 0 → 显示关闭文案且代理仍正常;`tunnel_logs` 返回同一份数据且 `name`/`limit` 生效;插件停用后日志清空

## 专项注意

- 端口与目标服务自备:隔离工位内起最小 HTTP/WS 目标服务(或 jupyter),不得探测生产端口。
- 子域模式依赖泛解析;无 DNS 时用 `*.localhost` 仅本机可解析,不能据此判公网形态通过。
- 危险操作:`tunnel_close` 会断开正在使用的目标应用;不要在共享终端/生产页面操作。
- 证据:九探针输出与 L3 截图落 `.compat/<版本>/`;失败行保留证据要同时看面板与 `tunnels.json`。
- 历史文档中的固定端口 18123 属人工流程记录,AI 会话按 AGENTS 自测规约用随机端口与本次实例。
- 已知限制(状态条弹窗): 嵌套弹窗同时保留 `aria-modal`,外层未 `inert`/`aria-hidden`;行内 `⋯` 菜单 portal 到 body 后不在弹窗焦点陷阱内,`Tab` 回绕不覆盖菜单,`Esc` 先关弹窗而非先收菜单。设置分区不受影响(本次仅在状态条弹窗复用该组合),后续可把菜单纳入 trap 或先收菜单。
- 测试缺口: 组件级渲染与弹窗交互(单条/多条文案、弹窗保活、时钟前进)无单测,由隔离宿主真机截图覆盖;`test/support/client-harness.mjs` 的 `useState` 不触发重渲染,单测只覆盖纯逻辑、注册与刷新门控。
