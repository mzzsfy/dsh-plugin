# dsh-bug-perf 兼容性测试

包定位:宿主缺陷的浏览器半区兜底。两个补丁各自独立开关、独立失败;任何结构不匹配只记录原因,不阻断页面。无 UI 槽位,断言走配置路由 + 页面内 `window.__dshBugPerf` 报告 + 页面行为观察。

## 测试分层与执行流程

| 层 | 内容 | 手段 |
|----|------|------|
| L1 单元层 | test/ 三个文件 34 用例(配置归一化、重启合并语义、看门狗判定与安装、host 路由) | 包目录 `node --test "test/*.test.mjs"` |
| L2 装载层 | 仓库 smoke 含本包;隔离环境 boot 无装载错误,console 出现 `[dsh-bug-perf] applied` | 仓库根 `node scripts/smoke-load.mjs` + 隔离 boot |
| L3 功能面层 | 下节断言:配置路由、默认安装、独立关闭、冻结自愈、合并计数 | 隔离环境 + playwright 页面探针 |
| L4 共存层 | 与全家桶共启,页面无 `Failed to load plugins`,两个补丁仍在报告 installed | 隔离环境全 bundle boot |

执行顺序:L1 → L2 → L3 → L4,前层失败即止。

### L2 判据

- 仓库根 `node scripts/smoke-load.mjs`:本包有 `OK   @mzzsfy/dsh-bug-perf` 行,全仓 0 FAIL。
- 隔离环境 boot:bundles = 三基座 + `@mzzsfy/dsh-bug-perf`;boot 日志无本包行级 failed to import / did not activate;页面 console 出现 `[dsh-bug-perf] applied` 且无 `Failed to load plugins`。

本轮实测(2026-11-07,0.2.2-rc.1 隔离工位,22 bundles 全家桶):`node scripts/smoke-load.mjs` 全 OK(含本包);`node scripts/compat/run.mjs --version 0.2.2-rc.1 --port 9303 --seed-gateway` 结果 `activation live=true findings=0`、`browser ok=true rendered=true hasFailBanner=false`,判定 PASS。profile bundles 22 个含 `@mzzsfy/dsh-bug-perf`(依赖为 `link:` 指向仓库包)。页面仅 3 条 `/login` 404(宿主登录态探测,与本包无关)。

0.2.1-rc.2 槽位实测(2026-11-07,`--only dsh-bug-perf --seed-gateway`):`activation live=true findings=0`、`browser ok=true consoleErrors=[]`、`importFailures=[]`、LLM 双协议往返 true;脚本判定 FAIL 的唯一原因是 `anthropicUpstream.userId` 为 `null`(judgeLlm 要求 `dsh:<40hex>` 的 gateway 标记断言,属 0.2.1-rc.2 宿主注释行为,与本包无关)。同工位功能探针:两功能 installed、20 次 `restart()`→3 次 attach、冻结 `revision` 26→27 自愈 + `terminal stalled` 日志 + `echo after-heal` 回显。据此 `dsh.hostMin` 定为 `0.2.1-rc.2`,`dshReleases."0.2.1-rc.2"` 记 `compatible`。

## L3 功能面断言

约定:`<port>` = 隔离环境端口,`<T>` = boot 日志 `token=` 之后的值。

### 一、配置路由面

说明:宿主的 `/api` 前缀有 cookie 会话闸门,直接 curl 无 cookie 返回 401(宿主认证行为,与本包无关)。先拿 boot token 换 cookie,或直接在页面 console 里 `fetch('/api/dsh-bug-perf/config').then(r => r.json())`。

| # | 操作 | 预期 |
|---|------|------|
| 1 | `curl.exe -s -c cookie.txt -o NUL "http://127.0.0.1:<port>/?token=<T>"` 换取 cookie,再 `curl.exe -s -b cookie.txt "http://127.0.0.1:<port>/api/dsh-bug-perf/config"` | 200,`content-type: application/json`,`config` 两节与 README 默认值一致 |
| 2 | 隔离 profile 行加 `config: {terminalWatchdog: {enabled: false}}` 后等热重载(约 1s),再请求 #1 | `terminalWatchdog.enabled` 为 `false`,`restartCoalesce` 保持默认 |

### 二、默认安装面

| # | 操作 | 预期 |
|---|------|------|
| 3 | 打开页面,console 执行 `window.__dshBugPerf` | `features.restartCoalesce.installed === true`;`features.terminalWatchdog.installed === true`(打开过一次终端后;未打开终端时允许为 `waiting for webTerminals` 后转 installed) |
| 4 | console 执行 `String(require?.('@deepseek-ai/dsh-api-gateway/client')?.RemoteStream?.prototype?.restart)`(页面模块表可达时)或观察 #6 的合并计数 | `restart` 函数名为 `coalescedRestart` |

### 三、独立开关面

| # | 操作 | 预期 |
|---|------|------|
| 5 | 行配置 `restartCoalesce: {enabled: false}` 后刷新页面 | `features.restartCoalesce.reason === 'disabled'`;`RemoteStream.prototype.restart` 保持官方原名(未包装) |
| 6 | 行配置 `terminalWatchdog: {enabled: false}` 后刷新页面,打开终端 | `features.terminalWatchdog.reason === 'disabled'`;`webTerminals.view` 未被包装(冻结场景不会自愈) |
| 7 | 两个功能都关闭后刷新页面 | 页面正常,console 无错误,`window.__dshBugPerf.features` 两节均为 disabled |

### 四、重启合并面

| # | 操作 | 预期 |
|---|------|------|
| 8 | 打开终端,在页面内对同一 stream 连打 20 次 `restart()`,每次间隔 5ms,记录 WebSocket `terminal/attach` open 帧 | 实际 open ≤ 窗口数 + 1(默认窗口 100ms 时约 2-3 次),而非 20 次 |
| 9 | 间隔 150ms 打 3 次 | 3 次均实际重开(窗口外不合并) |

### 五、终端自愈面

| # | 操作 | 预期 |
|---|------|------|
| 10 | 打开终端并点「接管输入」,执行 `echo ready` 确认可写;注入 10 个并发 `terminal/attach` 流后 dispose;再输入 `echo frozen` | 无回显,`view.state.revision` 停滞,`writable` 为 false(冻结指纹) |
| 11 | 继续等待 14 秒 | console 出现 `[dsh-bug-perf] terminal stalled, reconnecting`;之后输入 `echo after-heal` 回显,`writable` 恢复 true |
| 12 | 只读旁观视图(从未点接管输入)静置 30 秒 | 不触发自愈,不产生新的 attach open 帧 |

## L4 共存层

- 全家桶 bundles 共启:页面无 `Failed to load plugins`,两个补丁 report 仍 installed,终端与流式回复正常。
- 与 `@mzzsfy/dsh-shared-terminal` 共存:shared-terminal 的只读自愈与本包看门狗互不干扰(前者点「接管输入」,后者调 `view.connect()`),同一终端不出现重复重连风暴。

## 维度检查点(补充)

1. **官方形态复核**:宿主升级后逐项核对 `RemoteStream.restart`、`webTerminals.view`、模块表可见性;任一缺失时该补丁记 `waiting for ...` 或 `reason`,页面不报错。
2. **开关往返**:关闭 → 官方原名/未包装 → 重开 → 包装恢复;刷新与卸载后不残留包装。
3. **合并边界**:窗口内 20 次 restart → open ≤ 窗口数 + 1;窗口外逐次;不同 stream 不互相合并。
4. **看门狗边界**:未武装、页面隐藏、待渲染、无流、未连接均不触发;持续新帧不触发;冷却期不重复;新建视图自动武装。
5. **共存**:与 shared-terminal 同装时只读自愈走「接管输入」、看门狗走 `view.connect()`,两条路径不得同时抢同一终端。
6. **已知盲区**:本包是官方修复前的兜底,不是兼容性承诺;宿主已修复时应移除补丁而不是继续叠加。
